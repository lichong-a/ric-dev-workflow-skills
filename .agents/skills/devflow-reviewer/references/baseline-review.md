# BASELINE_REVIEW（基线审核）

对于有风险的 Brownfield 工作，在批准 Spec 前审核仓库画像、接管评估、基线证据和变更预算。

## 身份与 worktree

根据仓库事实验证 Git 根目录/ref/完整 SHA/upstream 和目标分支证据。检查 worktree 状态证据及重叠分析。任何对既有工作的自动 reset、clean、checkout、stash、覆盖或无归属提交都是阻塞问题。若不存在 Git，必须明确替代身份和限制。

## 侦察充分性

确认已检查：适用作用域指令；清单/锁文件/toolchain/CI；真实入口、调用、数据、公开契约、权限和部署路径；生成/vendor 区域；以及足以解释当前路径的相近稳定实现/测试，不强求凑数量。参考项必须有路径/符号和选择理由；文件同名并不充分。

检查风格画像是否区分强制规则、目标区域模式、不一致处和冲突处理决策。不能为了遵循不安全旧模式而牺牲安全或正确性。

## 续作与基线

续作场景要求对每个相关部分进行证据支持的分类：已接受、未验证、部分完成、桩、冲突、已放弃、未知或未开始；还要提供差距分析，以及选择扩展或重写的理由。默认沿现有纵向路径补全。

对每条基线命令验证 cwd、SHA、结果/退出证据和分类。声称既有失败时必须提供基线证明与相关性分析；目标路径仍需要可信覆盖或窄范围特征测试计划。

## 预算与结论

要求提供保守的允许/受保护路径，以及契约、数据、依赖、框架、构建、格式、生成文件、重构和写入者策略。无依据的大范围重构、丢失既有工作的分支重启、不安全脏改动重叠、关键路径缺失或错误基线分类都应形成阻塞发现。只有仓库画像足以支持无猜测设计时才可批准。

## 旧布局迁移对象

当交接明确为迁移完整性时，按[无损迁移](../../_devflow_shared/references/legacy-migration.md)核对精确候选、所有源文件的字节恢复、当前语义/关系、未知字段、原载荷、开放问题和失效 Gate。只读返回 BASELINE_REVIEW，不重审无关业务。临时草稿、缺少保全授权/基线身份为 BLOCKED；可审对象中的遗漏/错绑为 REQUEST_CHANGES。批准只覆盖转换，不构成新的产品批准。

# RELEASE_REVIEW（发布审核）

审核精确集成 SHA 和完整当前证据集。本审核不能替代代码审核或测试。

## 证据协调

- 每个计划 Task 均为 `VERIFIED`/`DONE`，且其实报告、代码审核和增量测试证据匹配已集成 Commit 血缘。
- 完整测试报告对该精确集成 SHA 和当前 Spec/测试计划版本给出 `PASS`；基线差异和未运行项均明确。
- Spec 审核、用户批准、测试审核、代码审核、决策和任何 P2 风险接受均为当前有效且未被取代。
- 不得遗留 P0/P1。P2 已修复或被授权所有者有效接受；P3 不得掩盖发布风险。

## 发布安全

验证目标分支及策略来源、集成祖先关系、迁移和混合版本顺序、配置/默认值、文档、Feature Flag 及清理、运维就绪、可观测性/告警、回滚或安全前滚修复，以及合并后冒烟计划。协调既有脏改动和历史失败，使报告精确说明本次发布证明了什么。

高风险工作还必须提供明确的权限/安全/隐私、数据恢复、失败、审计和有依据的性能证据。生产部署或其他外部写操作仍需独立授权；发布批准不授予该权限。

只有该 SHA 可以安全进入记录的目标时才返回 `APPROVE`。可修正的发布缺口使用 `REQUEST_CHANGES`；无法确立血缘或证据时使用 `BLOCKED`。任何集成变化都会使结论失效。

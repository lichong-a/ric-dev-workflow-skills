# 特征测试

仅用于必须保持兼容、但缺少可信覆盖的受影响 Brownfield 行为。

## 有意识地选择行为

追踪真实公开/用户/系统边界，选择新变更可能意外改变的最小可观察行为。确认 Spec 并未要求改变它。不要为每个内部细节建立特征测试，也不要把明显缺陷、漏洞、非确定值或偶然格式固化成永久契约。

记录输入、环境/完整 SHA、当前结果、必须保持的原因和稳定断言。优先断言语义字段与不变量，而不是大型快照。只规范化时间戳/ID 等真正不稳定的元数据，同时保留有意义的顺序、错误和副作用行为。

## 建立证据

在修改生产代码前，针对基线运行新特征测试，并记录它对预期当前行为通过。若无法通过，或该行为是否合理尚不确定，不得改写预期；应把歧义报告给规划者处理 Spec/风险决策。

实现后，在精确 tested SHA 上重新运行。如果结果变化，则视为回归，除非当前已批准 Spec 明确取代该行为。

若测试保护长期兼容边界，应保留在仓库。若只用于诊断，应说明能否及何时移除；不得为获得通过结果而悄悄删除。

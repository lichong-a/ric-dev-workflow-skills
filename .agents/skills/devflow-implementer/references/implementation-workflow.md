# 实现工作流

## 定位并保持契约

从 Task 指定的用户/系统入口开始，追踪校验、授权、领域规则、数据/外部 Adapter、序列化/错误、可观测性和测试。确认 Spec 改变哪些当前行为、保持哪些行为。检索可复用代码，以及规划者记录的相关稳定示例；验证它们在 base SHA 上仍然准确。

将拟变更文件映射到 AC，或必需的风险、兼容性、测试和文档工作。若必要文件不在允许路径内，或会改变公开/数据/构建/依赖策略，则在编辑前停止并请求预算或 Spec 决策。

## 实现完整纵向行为

优先使用已有依赖和边界完成直接、局部的解决方案。先在权威服务/领域/数据库层强制不变量，再接通真实入口路径、稳定错误和副作用。根据 Task 风险处理缺失/null/空值/边界、权限拒绝、部分失败、重复/重试/并发、超时/取消、资源清理和兼容性。

在没有真实第二个变化点或边界前，不要增加抽象。Adapter、Strategy、Factory/Builder、Middleware/Decorator、State、Repository、Outbox/Inbox、Saga 或 CQRS，只有在解决已批准设计描述的具体问题且仓库架构支持时才可采用。

## 测试与文档

使用已有测试框架和风格，为分配到本 Task 的成功、失败、边界和回归行为添加测试。优先断言可观察结果和真实本地边界，避免 Mock 内部调用。控制时间、随机数和网络，清理数据，并使用有界等待。除非 Task 明确分配，否则不要重复测试者负责的跨模块/E2E 工作。

通过生成器更新生成契约，通过仓库工具执行迁移；行为变化时同步公开/配置示例和行为文档；补充功能运维所需的结构化脱敏诊断。适用时包含部署/回滚顺序。

## 按范围递增验证

运行语法、格式和 diff 检查，聚焦单元/组件/模块测试，相关 Lint/类型/静态检查，受影响集成/契约测试，以及风险和成本允许的构建或更广检查。精确记录失败；只与已证明的基线证据比较。不得通过全局 ignore、删除测试、重试循环或抑制警告来获取通过结果。

# 产物生命周期

持久产物是事实源，对话不是。布局与证据身份按本契约执行，角色权利不因文件合并而改变。

## 布局路由与稳定 ID

新 Root Issue 默认使用 [Compact v2](../references/compact-layout.md) 与 [四文件模板](../templates/compact/state.yaml)，按进度创建文件，不预建空目录。既有 `schema_version: 1` 继续按原布局读取和运行；旧模板保留在 `templates/` 根目录。检测到旧版本目录时，Planner 只提出一次[无损迁移建议](../references/legacy-migration.md)，未经授权不切换。

沿用 Root Issue `REQ-YYYYMMDD-NNN`、`TASK-NNN`、`AC-NNN`、`REVIEW-NNN`、`TEST-NNN`、`IMPL-NNN`、`DEFECT-NNN`、`DECISION-NNN` 或仓库已有不冲突的 ID。跨文件引用必须能定位精确对象，不能只写“最新版”。

## 草稿、发布与取代

- 草稿可连续原地编辑，不为内部预检、commentary 或每次保存制造正式修订或提交。状态可索引草稿，但不能把它作为有效 Gate 证据。
- 正式送审前固定对象修订与不可变身份：Git 完整 Commit SHA + 路径 + 对象 ID；无 Git、不能跟踪或没有提交授权时保存不可变本地快照及内容哈希，注明仅本地可恢复。代码门禁所需 SHA 不能用文档哈希替代。
- 一经交给独立 Reviewer 或产生正式结论，被审内容即已发布；被拒绝或阻塞的版本也须可逐字恢复。v2 的固定正文文件可以继续修订，历史由 Git 或快照冻结；v1 已发布的旧路径不可覆盖。
- 每个 Task 独立修订。局部修改不递增无关 Task/测试用例版本，不复制 Root、Profile、Decision 或整套矩阵。
- 审核、测试、实现、Defect 的已发布记录不可修改；修正由原职责作者发布新 ID/版本与 `supersedes`。v2 在 `evidence.md` 追加，v1 新路径发布。历史结论始终保留原绑定。

## 有效性而非父文件版本连锁

| 证据 | 原绑定始终保留 | 当前使用要求 |
|---|---|---|
| Spec 审核、用户批准 | Spec 对象修订与文档身份 | 受影响行为变化重开 G2/G3；含义未变按变更控制记录适用性 |
| 测试审核 | Spec、测试计划对象修订与身份 | Oracle/权限/环境边界变更重开受影响 G4；纯职责映射局部复核 |
| 代码审核 | Task、Spec、完整 `base_sha..head_sha` | head 或相关行为变化需新的绑定审核，可按风险增量复审 |
| 测试报告 | Spec、计划、环境、完整 `tested_sha` | 仅证明原输入；代码、环境、必要输入改变需按影响补充验证 |
| 发布审核 | 集成 SHA、证据集 | 当前集成 SHA 和覆盖必须一致，不能用后续记账提交冒充受测候选 |

沿用旧批准时，以新适用性记录说明旧/新对象、精确 Delta、未受影响范围和复核依据；不得篡改旧载荷、空写“继续有效”或把旧 `tested_sha` 换成新 SHA。详见[变更控制](change-control.md)。

## 持久化与恢复

各角色独立生成完整载荷；Planner 原样追加到账本，仅承担传输，不获得作者或批准权。作者发现错误时另发取代记录，不由 Planner 改写。失败、阻塞、未运行项同样属于正式证据。

先写完整证据、验证 ID 和载荷，再更新状态索引。中断恢复先核对记录 ID：同 ID 同载荷复用，不重复追加；同 ID 异载荷阻塞并向作者求解。未完成写入不得被状态引用；临时草稿可重建，已完整发布的记录不得覆盖。正式证据不能只依赖 `.local/`；可复现条件不足时保留必要脱敏附件。

只有 Planner 可以更新 `state.yaml`。v2 状态只保留当前索引；事件、历史状态、Finding 处置和适用性结论进入账本。矛盾证据未解决前，对应 Gate 保持未通过。

# 变更控制与收敛

按对象的真实影响传播，不按父文件版本传播；布局变化不弱化安全、权限、用户批准或 SHA 门禁。

## 当前对象修订

正式修订记录类型、原因、受影响 ID、精确 Delta、旧/新身份和适用性证据。草稿可以连续编辑，正式送审才固定身份。

| 类型 | 影响 | 处理 |
|---|---|---|
| `EDITORIAL` | 拼写/格式，含义不变 | Planner 记录精确差异和无语义影响依据，不单独调用 Reviewer；原批准仍绑定原对象，不能把新修订写成已审 |
| `TECHNICAL` | Task 预算/批准的内部约束，行为不变 | G2 局部技术复审；Task 内执行顺序/检查点且不改批准约束不属此类，无须送审 |
| `TECHNICAL` | DAG 节点/依赖/所有权边界变化，行为不变 | 先满足冻结例外，再 G2 局部复审受影响节点/边；不重建完整 DAG |
| `TECHNICAL` | 测试职责或 AC 映射调整，Oracle/环境不变 | Tester 更新有关映射，G4 局部复核；未变化用例不再发布 |
| `BEHAVIORAL` | AC、API/数据/UI、错误、权限、安全、兼容或测试预期变化 | 使受影响 G2/G3/G4 及下游证据失效；返回对应门禁，不在过期批准下继续实现 |

只递增真正变化的对象独立修订，文件 Change Log 可递增但不令所有 Task 的 `spec_version` 被动改写。未变对象直接引用原批准。纯过程变化不修订批准对象；EDITORIAL 可继续使用原已审对象作为执行依据，记录新文本但不宣称新对象已获批准。确需将批准适用到新 TECHNICAL 对象时，仍由独立 Reviewer 给出旧/新身份、Delta 和依据；纯文字修订的适用性确认可并入下一次相关审核，无须为此单开会话。语义不确定则按实际风险复审。用户行为批准原文保留，Planner 不能替用户批准新行为。

DAG 冻结、例外条件和最小变更记录统一按[Task 与冻结 DAG](../../devflow-planner/references/task-decomposition.md)。根因分析、预算不足或局部环境 BLOCKED 不是自动改图授权；先在原 Task 内解决，不能通过新节点把每轮返修变成新的完整研发流程。

## Commit、环境与证据

代码 Review 只绑定原 `base_sha..head_sha`；测试报告只绑定原 `tested_sha`、计划、环境和必要输入。移动分支名、文档记录提交或新 head 都不能替换原绑定。代码、环境、必要输入变化时按影响补充审核和验证，新的报告诚实区分新运行与引用旧结果；影响未明的部分不能沿用。

相同 SHA、环境、命令、数据条件、Oracle 和范围均未变化的有效结果可引用，先核对覆盖，不例行重复执行。Implementer 自测，Tester 独立验证，Reviewer 按风险核验，Planner 核对身份/覆盖，不例行再跑完整套件。独立验证不得退化成复制 Implementer 的自测结论；必要缺口/失败才触发补查。

测试代码也是候选代码：即使 Oracle 和计划未变，G5 后修改测试也须在原 Task 内发布真实作者的代码交付报告、复审新 SHA 并重新集成验证，暂时撤销受影响 Task 的有效已验证状态。仅测试实现修正不重开 G4；Oracle、环境或权限变化仍按上表复核。不能把未提交的新测试执行结果绑定为旧候选的正式 `PASS`。

## Finding、复审与停止

首轮完成当前审核对象全部适用维度，一次返回当时可发现的全部 P0/P1/P2 Finding。推测性优化和无关技术债不进入返修链；真实严重新问题即使复审时才发现也必须报告，说明证据而非隐藏。

稳定 Finding ID 的处置为 `resolved`、`unresolved`、`accepted` 或 `not_applicable`，逐项附证据，不能只写“已按意见修改”。`accepted` 仅适用于有效且有权批准的 P2 风险接受；P0/P1 不得绕过。

窄修正默认复用独立且可用的原 Reviewer，只查 Delta、旧 Finding 和受影响邻域；新 Review 使用新 ID 和 `supersedes`。Reviewer 不可用/有职责冲突时交接审核谱系并完整复审；行为、架构或风险显著扩大时完整复审当前受影响范围，不扩成全仓审计。

同一对象/模式连续两次 `REQUEST_CHANGES`：暂停下一轮送审，归并重复/新增 Finding，找出事实预检、Spec 结构、测试模型、架构约束或范围失控的实际原因，针对性修正后再审。同一 Defect 连续三轮失败：停止重复补丁并归因。两者独立计数，不以改文件名/版本/Review ID 重置同一对象循环，也不默认重建全部 Spec/DAG/测试计划。

新增需求不伪装成 Defect；记录延期或另建阶段，行为及重要取舍变化须由用户批准。

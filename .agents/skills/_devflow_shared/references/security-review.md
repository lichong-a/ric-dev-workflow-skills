# 安全审核

HIGH_RISK 工作，以及认证、授权、租户/数据访问、上传、回调、解析、secret、支付、管理操作或公开入口发生变化时，加载本参考。

## 以威胁为中心的检查

识别资产、参与者、信任边界、入口、特权操作、滥用目标和失败影响。沿真实授权路径检查动作、资源归属、租户、角色和对象级权限。默认拒绝；客户端检查和 CORS 都不是授权。

所有外部输入和历史存储输入都视为不可信。按适用性检查注入、XSS、CSRF、SSRF/DNS 重绑定、路径穿越、开放重定向、原型污染、不安全反序列化、命令执行、请求走私，以及解析器/资源耗尽边界。

上传必须限制大小、数量、类型和内容，生成安全存储名，放在不可执行位置，隔离解析器，配置访问控制和清理。URL 抓取器必须使用协议 allowlist，在 DNS 解析与重定向前后防御私网地址，限制大小和时间，并且不得转发凭据。

## Secret、隐私与密码学

使用已有 secret 存储和成熟密码学。绝不能把密钥、Token、Cookie、连接串、个人数据或生产样本写入代码、状态、日志、测试、快照、Prompt 或报告。最小化采集并记录保留/删除/审计策略。对外错误不能暴露堆栈、SQL、路径或安全敏感差异。

## 供应链与默认值

优先使用已有依赖。对已批准新增依赖审核维护状态、来源、锁文件变更、传递依赖、许可证、安装 Hook 和安全公告。使用安全默认值和最小权限，限制速率/配额，审计敏感操作，并默认关闭危险能力，只有明确启用后才可使用。

## 发现与证明

报告可利用或合理成立的攻击路径，包括前置条件、受影响资产、影响、证据和最小安全修复方向。避免把推测性的扫描器噪声当成发现。要求在权威边界提供回归测试，并确认修复没有只是把检查移动到可绕过层。

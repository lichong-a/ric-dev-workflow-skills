# 前端审核

涉及用户界面 Spec、实现、测试或发布审核时，加载本参考。

## 产品与状态行为

- 从真实路由/动作追踪主要流程和恢复流程，并保持 Spec 范围外的 URL、导航、历史记录和既有交互契约。
- 覆盖加载、空数据、错误、成功、禁用、无权限、离线、部分成功、重复提交、过期响应及卸载/取消行为。
- 状态放在最小合理作用域：可分享状态放 URL，远端数据放仓库既有 server-state 层，表单状态留在表单，局部 UI 状态保持局部。不得引入平行状态系统。
- 乐观更新必须有明确回滚和服务端对账路径。

## 优先使用现有设计系统

识别并复用组件、Token、图标、布局原语、反馈模式和相邻页面。拒绝引入第二套组件库、隔离的 Token 集合或无关视觉重设计。使用真实内容长度和目标断点验证；项目支持时覆盖移动端、平板和桌面端。

## 可访问性与国际化

检查语义元素、可访问名称、键盘顺序/操作、可见焦点、对话框/错误/导航后的焦点移动、实时播报、对比度、减少动态效果、触控目标、缩放/重排和屏幕阅读器状态。消息、复数、日期、数字、货币和 RTL 使用既有 i18n 系统；不得拼接自然语言片段。

## 安全与性能

把所有渲染数据视为不可信。检查 XSS、不安全 HTML/URL、开放重定向、进入查询参数/本地存储/日志的敏感数据、CSRF 假设和服务端授权。根据真实风险或测量结果检查请求瀑布、代码/图片体积、Hydration/运行时边界、列表上限/虚拟化和缓存行为。不得一概 memoize。

测试应使用仓库工具断言用户可观察行为；避免大型快照和脆弱的组件内部断言。条件允许时，对关键布局、焦点、导航和网络流程使用真实浏览器。

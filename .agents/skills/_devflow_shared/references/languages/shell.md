# Shell

仅当范围涉及 Shell 脚本或基于 Shell 的 CI/构建行为时，加载本参考。

- 遵循声明的解释器；不得把 Bash 语法引入 POSIX `sh`。仓库允许新增 Bash 脚本时，使用明确 Shebang 和稳健错误处理（如 `set -Eeuo pipefail`），并理解 Trap 行为。
- 引用参数展开和路径；Bash 中使用数组传参。不得 eval 或拼接不可信命令文本、解析 `ls`、依赖 Locale 相关输出，或在破坏性操作中使用宽泛 Glob。
- 写操作前验证目标，使用 `mktemp` 配合清理 Trap，避免常见系统变量名，并在可能重跑时保持幂等。
- 不得通过参数、Trace、进程列表、日志、产物或命令替换暴露 secret。避免远程 `curl | sh` 和未经验证的下载二进制。
- 限制子进程耗时和并发，传播退出状态，区分预期无匹配与失败，并在收到 Signal 时清理子进程/资源。
- 运行仓库检查，以及已有的 `shellcheck`/格式化器。测试空格、换行、空值、命令失败、重复运行和清理。

DevFlow 本身是纯指令系统：不得新增 DevFlow Shell 编排器。

# 数据库审核

范围涉及 Schema、查询、迁移、事务、以数据库状态为基础的缓存，或数据修复/回填时，加载本参考。

## 不变量与查询

- 在数据库支持范围内，用主键、外键、唯一、非空和 check 约束保护持久不变量；应用错误映射要能正确处理约束竞争。
- 审核真实查询形态、谓词与选择性、排序、限制、Join、N+1、隐式转换和 ORM 生成的 SQL。当数据量或延迟使其成为实质风险时，检查执行计划。
- 显式选择列并绑定参数。每个租户查询和缓存键都必须限定租户。稳定分页需要确定性平局规则；大数据集通常需要游标。
- 事务保持短小，并明确隔离/锁行为。避免事务内慢网络调用；仅在安全且有界时处理死锁和重试。

## 迁移安全

使用仓库的迁移工具。破坏性或大表变更优先采用“扩展 → 部署兼容读写方 → 回填 → 切换 → 收缩”。评估锁、WAL/日志量、磁盘、运行时长、副本延迟、回滚可行性和混合应用版本。大表默认值和约束可能需要分阶段应用。

回填必须有界、幂等/可重入、可观测、可暂停/恢复，并能在并发写入下安全运行。记录进度和对账。绝不能使用未脱敏生产数据测试。

## 数据语义

金额使用精确十进制或最小货币单位；时间使用 UTC 时刻并显式指定展示时区；编码/排序规则要明确；删除/归档/审计行为要显式。删除前应厘清所有权和级联行为。

## 证据与恢复

要求提供迁移升级/兼容测试、受影响查询测试、约束/竞争测试；风险需要时提供有代表性的执行计划或 Benchmark；同时提供部署顺序、监控，以及回滚或安全前滚修复/数据恢复方案。无法回滚的迁移必须在批准前明确说明。

# 仓库侦察

Brownfield 需求接收、基线审核，或修改陌生仓库之前，应阅读本参考。侦察应与任务规模相称并保持聚焦。

## 建立不可变上下文

记录 Git 根目录、当前分支/ref、完整 HEAD、upstream、worktree 状态、submodule/worktree 和可能的目标分支。侦察期间不得修改 worktree。若不是 Git 仓库，记录 `NO_GIT`，说明哪些证据无法绑定 SHA，并尽可能使用稳定文件哈希或有版本产物；不得虚构 Git 语义。

找出从仓库根到目标路径所有适用的指令文件。作用域冲突时记录最终采用哪条指令。阅读最近的 README、贡献/构建说明、ADR、清单、锁文件/版本文件、格式化/Lint/类型配置、迁移、生成代码标记，以及实际覆盖目标区域的 CI Job。

## 追踪行为，而不是只看文件名

从外部可观察入口开始：Route、命令、事件消费者、Job、UI 动作、库导出、迁移或部署资源。沿调用链追踪到授权、校验、领域逻辑、存储、外部 Adapter、错误映射、序列化、日志和测试。标记运行时边界，以及生成数据或历史数据进入的位置。

检索两到三个相近实现。优先选择相同模块/领域、当前公开契约、有通过的测试/CI、近期仍维护的代码，而不是只看全仓出现次数。记录精确路径和符号，以及哪些模式可以安全复用。仅名字相似不能构成证据。

## 推导本地约定

为模块边界、构造/DI、命名/import、错误、配置、日志、并发/事务、API/数据、UI 模式、测试/fixture/mock 和迁移提供具体示例。区分强制规则与常见倾向；对于不一致区域要如实记录，不能平均成虚构的统一风格。

## 映射目标仓库交付协议

识别仓库已有的 Issue、设计/审批、测试计划与报告、CI、发布和状态事实。在仓库画像现有的“生效指令与文档”“冲突与选定规则”及目标路径描述中，记录它们与 DevFlow G0–G10 的语义映射。只有当范围、独立所有者、版本或完整 SHA、时效性和证据可读性等价时才复用；引用原始身份，不创建内容相同的第二份产物。冲突时使用更严格规则并记录依据。

同时记录验证环境层级和授权边界：合成/Mock、本地真实边界、集成环境、live 服务和生产操作分别能证明什么，哪些当前可用，哪些需要额外授权。不得读取或索取不在任务授权内的凭据。

## 基线命令

使用仓库提供的命令。先运行窄范围检查；成本和环境允许时再扩大。每个结果都要记录命令、cwd、相关环境（不含 secret）、完整 SHA、退出码、简明证据，以及以下分类之一：`clean`、`pre_existing`、`environment` 或 `unknown`。只有证据证明失败在 DevFlow 变更前的基线中就存在，才能归类为既有失败。

## 停止条件

以下情况必须阻塞相应工作：重叠脏文件无法安全隔离；无法确定目标/源分支；必需验证需要未授权凭据或生产访问；生成源缺少生成器；受影响行为没有可信基线且无法安全建立特征测试。若环境或授权缺失只影响可独立拆分的验证切片，应记录边界并只阻塞该切片，不得擅自访问，也不得无依据阻塞整个 Root Issue。

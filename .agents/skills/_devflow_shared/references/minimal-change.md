# 最小完整变更

定义或审核 Brownfield 变更预算时，使用本参考。

## 最小化行为和所有权范围，而非牺牲完整性

最小变更只改变请求行为和必需支撑路径，但仍需按风险覆盖校验、失败行为、测试、文档、迁移、可观测性和回滚。不能仅为缩小 diff 而省略错误路径或硬编码成功。

必须定义：

- 允许改变的可观察行为；
- 必须保持兼容的行为；
- 精确的允许路径与受保护路径模式；
- 公开 API/事件/配置/数据策略；
- 依赖、框架、构建、生成代码、格式化和迁移策略；
- 每个共享区域的唯一写入者；
- 预期文件，以及任何不确定路径的理由。

## 重构防火墙

`REQUIRED` 表示不执行该重构就无法安全或正确完成任务；必须纳入 Spec 与预算。`INCIDENTAL` 表示极小的局部编辑直接降低必需变更的风险；由审核者决定是否保留。`OPPORTUNISTIC` 表示清理、现代化、通用化抽象或个人偏好；应从本次变更移除，必要时单独记录后续工作。

范围漂移信号包括：整个文件或全仓格式化、大范围重命名或移动、没有已批准依赖工作的锁文件变动、替换本地错误/数据模式、只为一个调用点创建抽象、编辑无关失败测试，或为了规避局部解决方案而修改构建/共享配置。

## Diff 审核问题

对每个变更文件都要问：哪个验收标准或必需风险控制需要该文件？已有本地能力能否满足？它是否改变未声明契约？是否包含用户的既有工作？能否安全独立回滚？无法给出充分答案的文件超出预算。

安全或正确性可能要求局部偏离不安全的遗留风格。此时应复用已有安全 API，保持周边结构一致，说明偏离原因，并且不得借机现代化整个遗留区域。

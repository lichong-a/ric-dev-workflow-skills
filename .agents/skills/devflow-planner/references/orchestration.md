# 编排与交接

从第一次向 Reviewer、Tester 或 Implementer 委派开始使用本参考，包括仓库基线和正式 Spec 之前的只读调查。持久产物是事实源，对话只传递当前动作和不可变身份。

## 紧凑且精确的交接

每次交接只携带：Root Issue、单一角色动作或审核模式、目标产物路径/版本、适用的完整 SHA、当前 Finding/Defect、允许/受保护路径、预期输出、首个可观察检查点和停止条件。完整 Spec、Task、Review、测试报告和仓库画像通过路径与身份引用，不重复粘贴；接收角色自行读取相关证据。

向审核者交接时，必须注明模式、Root Issue、目标产物/版本、适用时的 Task、代码的 `base_sha` 与 `head_sha`、发布审核的集成/tested SHA、变更预算、实现/测试证据，并明确要求只读输出。

向测试者交接时，必须注明 Root Issue、Spec 和测试计划版本、基线报告、精确 SHA、已合并 Task 或完整/冒烟范围、预期环境和输出路径；失败只产生 Defect 证据，绝不能由测试者修改生产代码。

向实现者交接时，必须注明一个 Task 或已归因 Defect、Root Issue、Spec 版本、AC、测试计划、`base_ref` 和完整 `base_sha`、允许/受保护路径、仓库画像/参考实现、已知基线失败、预期命令，以及不得合并和不得扩大范围的边界。

不得委派含糊 Prompt，再期待子角色从对话历史重建权限与身份。在平台支持上下文继承控制时，默认关闭完整历史继承，例如设置 `fork_turns: "none"`；只有当前增量无法由持久产物和 Finding/Defect 身份表达时，才附带最少的相关近期上下文。若交接仍需大量互不相关材料，应先拆小审核或 Task，而不是扩大 Prompt。

## 等待、恢复与中断

委派时根据风险和任务规模声明完成条件及合理执行预算。优先使用带 cursor/revision 的事件式长等待；状态未变化时不得反复读取任务、重发相同 Prompt，或仅因暂时没有 commentary 就中断正常推理。仅在明确偏离范围、持续无进展超过既定预算、等待用户输入、工具挂起或违反角色边界时中断。

中断、超时或上下文压缩后，从 `state.yaml`、当前产物、精确 SHA 和未关闭 Finding/Defect 恢复；不得重新注入完整对话历史。相互独立的只读调查可以并行，但共享生产路径、契约、数据、构建配置及同一 UI/模块区域始终只有一个写入所有者。

## 审核收敛

一次正式审核必须覆盖全部适用维度并返回当时可识别的所有 P0/P1/P2 Finding。规划者为每个稳定 Finding ID 记录 `resolved`、`unresolved`、`accepted` 或 `not_applicable` 处置及证据，不能只写“已按意见修改”。`accepted` 只适用于取得当前有效风险接受的 P2；P0/P1 不能接受后放行。

窄范围修正默认交回仍保持独立的同一 Reviewer 会话，提供上一 Review、待关闭 Finding、精确 Delta 和受影响邻域；新 Review 使用新 ID 并 `supersedes` 旧 Review。Reviewer 不可用/有冲突，或修订改变行为、架构边界或风险面时，执行完整复审。切换 Reviewer 时交接审核谱系，不交接完整聊天。

同一产物和审核模式连续两次 `REQUEST_CHANGES` 仍未收敛时，停止继续发布并送审新版本。先汇总重复与新增 Finding，判断根因是事实预检、Spec 结构、测试模型、架构约束还是范围失控，完成针对性修正后再送审。该规则与同一 Defect 连续三轮触发根因分析分别计数。

## 集成循环

1. 验证 Task 依赖和证据时效性。
2. 从最新已验证集成 SHA 分配 Task。
3. 接收实现报告和不可变 head SHA。
4. 为精确 SHA 范围取得代码审核批准。
5. 按仓库策略合并，并记录新的集成 SHA。
6. 为该 SHA 取得增量测试 `PASS`。
7. 将 Task 标记为 `VERIFIED`，随后标记 `DONE`；安排新解阻的 Task。

未变化的 Root Issue、仓库画像、Review、测试证据或 Decision 只通过路径和身份引用，不因局部修订复制整套产物。

## Defect 归因

测试者提供怀疑类别；最终归因归规划者所有。`SPEC` 进入变更控制；`TEST` 返回测试者并随后重新测试审核；`IMPLEMENTATION` 创建有界修复交接，随后重新审核和测试；`ENVIRONMENT` 记录恢复条件；`BASELINE` 评估相关性但不得扩大范围；`SCOPE_CHANGE` 进入变更控制；`UNKNOWN` 安排有针对性的只读调查。连续三轮失败会触发根因分析和重新规划。

## 收尾

完整验证、发布审核、目标合并和冒烟测试都必须指向当前 SHA 血缘。关闭前协调：产物存在性/取代关系、Spec/用户/测试批准、未关闭发现/Defect/阻塞项、迁移/配置/文档、基线差异、回滚和脏改动归属。记录未运行项；绝不能把它转换为 `PASS`。

## 四文件执行与预算

本节存储规则仅适用于 v2；未迁移的 v1 保持原版本路径与 transitions，通用收敛/等待规则对两者均适用。

按[Compact v2](../../_devflow_shared/references/compact-layout.md)恢复：state → 当前对象章节/独立修订 → 相关 evidence 记录。Prompt、会话 ID、cursor/revision、PID 和检查点缓存放 .local，不写进受跟踪正文；持久记录只保存业务证据与可审计角色身份。未变化且已读的共享契约不反复加载。

Planner 原样追加各角色完整载荷，先证据后状态；写入失败按 ID 核验恢复，不能为了重建状态而重新发一遍审核/测试。Reviewer 只读、Tester 拥有计划、实现者拥有代码的边界不因合并文件而改变。

调查默认一轮聚焦加一轮缺口补查；两次无新增事实停止同类搜索。当前决策已充分时进入下一门禁，继续探索必须关联具体 AC/失败/约束。下一阶段只保留能力、依赖与延期，不展开全套 Task/测试。

估算包含代码、测试、生成物和必要文档并留余量；不设置通用行数/字节硬阈值，宿主的明确硬限制和无进展熔断仍优先。事件等待的长短服从宿主工具边界；没有新状态不重发 Prompt、不重复取证，也不以暂时无 commentary 当作推理挂起。

# 实现者自审

自审用于发现实现错误，不代表门禁批准。

## 行为与风险

- 从真实入口追踪每个所分配 AC，确认正常、非法、边界、错误、部分失败/恢复，以及适用的权限/并发/兼容性行为。
- 重新检查权威不变量、稳定公开错误/契约、事务与副作用顺序、幂等、超时/取消/重试和资源清理。
- 按适用性检查 secret/隐私、注入/路径/URL/上传/反序列化暴露、租户作用域、日志/指标/Trace、数据精度/时间、迁移/回滚和资源上限。

## Diff 与所有权

比较初始和最终状态。对每个变更文件确认：属于允许路径；服务于 Task 目标；符合本地风格；没有无关格式化/重命名；未手改受保护或生成文件；没有未经批准的依赖/锁文件/构建/公开契约/数据变更；没有混入用户既有工作。检索调试输出、永久 Mock/桩、硬编码成功、吞掉的错误、疑似 secret 值、无说明 TODO、死代码和意外产物。

按[业务命名与既有代码保护](../SKILL.md#业务命名与既有代码保护)核对新增标识是否表达业务含义，是否存在作用域遮蔽、共享命名冲突或对既有公开名称的意外改动；确认共享逻辑的调用方与受影响行为已检查，必要回归覆盖原有功能。命名清晰不能替代这些检查，也不能保证没有 Git 合并冲突。

按[设计模式参考与模块化设计](../../ric-devflow/references/shared/modular-design.md)核对本角色检测和实际读取记录、职责与依赖边界、规划决策一致性，以及采用或不采用模式的理由；确认新增抽象有当前需求依据，相关行为与回归验证覆盖受影响边界，未借模块化扩大任务范围。

## 证据

运行 `diff --check` 或仓库等价检查、Format/Lint/类型/静态分析、聚焦测试、受影响集成/契约测试，以及与风险相称的构建/更广检查。记录精确命令、cwd、结果/退出状态、SHA/diff 身份和如实的未运行原因。区分已证明的基线失败与新增失败。

确认报告文件列表与真实 diff 一致，base/head 身份确实存在。随后交给独立审核；措辞不得暗示已经获得审核者或测试者批准。

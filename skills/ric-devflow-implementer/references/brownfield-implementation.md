# Brownfield 实现

## 优先续作，再考虑替换

阅读接管清单并检查 base SHA。保留 `ACCEPTED_COMPLETE`；验证 `COMPLETE_UNVERIFIED`，或补充缺失证据；沿现有纵向路径完成 `PARTIAL` 和 `STUB`；只解决已批准的 `CONFLICTING` 工作；除非 Task 明确负责，否则不得删除 `ABANDONED`/`UNKNOWN` 条目。重写必须有已批准的正确性、安全、兼容性或可行性理由。

## 安全继承本地风格

沿用最近稳定模块的命名、边界、构造/DI、错误/响应、日志/配置、异步/事务/重试、UI/数据/状态、测试/Fixture 和迁移模式。强制编译器、Lint、测试和 CI 规则优先。不得顺手统一无关模块的不一致风格。

若邻近风格不安全或不正确，应使用项目中已有的最小安全机制，保持周边结构不变，在权威边界添加回归测试，并记录偏离原因。不得复制缺陷，也不得把局部修复扩展成遗留区域整体重写。

## 保护 worktree 与预算

编辑前及每个完整阶段后都要记录状态/diff。不得覆盖、stash、reset、clean、提交或重新格式化用户既有改动。发现重叠时，在写入前停止，并请求规划者决定隔离/归属方式。

每个变更文件都必须关联其 Task 用途。拒绝未经批准的锁文件变动、新依赖、框架/构建/包管理器迁移、大范围移动/重命名、全仓格式化、公开/数据契约变化、手改生成文件、跨模块抽象，以及无关历史测试或技术债修复。

若极小的伴随重构能直接降低当前风险，应为审核者记录其文件和用途。必要重构必须已纳入 Spec/预算；机会型重构不得进入本次变更，但可以单独提议。

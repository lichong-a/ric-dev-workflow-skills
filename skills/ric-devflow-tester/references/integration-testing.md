# 集成、完整验证与冒烟测试

## 增量集成

规划者每次合并后，解析新的完整集成 SHA。验证已合并 Task 的祖先关系，并运行其映射验收用例、边界/契约测试、相关特征测试和受影响回归。如果 Task 触及共享契约、数据或构建，还要覆盖相邻消费者。将失败与已记录基线比较；在证明并非新增之前，任何新失败都属于当前失败。

为该 SHA 发布一份报告。后续再合并后，即使命令相同，也必须创建新报告。

执行前按[测试代码交付](../../ric-devflow/references/shared/test-code-delivery.md)核对生产代码、测试代码和依赖的实际身份。发现需要新增/修正测试时交回原 Task 的代码交付路径；新测试尚未纳入受审候选前只作诊断，不能把其通过结果归到旧 tested_sha。G6 通过后 Task 保持 VERIFIED，目标冒烟与关闭之前不置 DONE。

## 完整验证

所有 Task 集成后，验证 Spec/测试计划版本，并运行全部必需 AC 用例、跨模块契约/集成、E2E 或真实浏览器流程、受影响回归和计划中的完整回归、风险边界探索，以及有依据的安全/性能/迁移/恢复用例。模拟真实顺序、数据形态、角色、重复动作和失败，而不只测试孤立 Happy Path。

记录环境/服务/浏览器/设备/配置版本、数据准备/清理、命令、退出码、产物、未运行原因、剩余风险、基线差异和精确集成 SHA。避免生产副作用。

## 合并后冒烟测试

合并后解析目标分支完整 SHA。运行预先声明且与变更匹配的关键启动、健康、主要成功流程、关键授权/数据边界，以及迁移/配置检查。冒烟测试不能取代完整验证，也不得扩大成未经批准的生产写入。

若冒烟失败，应发布 `FAIL`/Defect 证据并返回规划者协调回滚或 Hotfix。不得自行回滚生产，也不得声称此前集成证据足以证明已变化的目标 SHA。

完整验证可以引用同一 SHA、计划、环境、数据条件和命令范围下已有的独立有效执行结果，并在新汇总报告中标明引用与新运行范围，不伪造再次执行。新集成/目标 SHA 的必需验证仍按门禁执行；失败或缺口需补查，不通过无限重试或增加超时掩盖。正式命令及关键输出持久化到账本/必要附件，不能只给 .local 日志路径。

# Defect 报告

每个可独立处理的失败创建一个不可变 Defect 产物。只有证据表明症状来自同一根行为时才合并；否则应保持复现步骤和所有权清晰。

包含 Root Issue、Defect ID、完整 `found_on_sha`、当前 Spec 版本、严重度、受影响 AC、精确环境/配置（脱敏）、前置条件/数据、最小有序复现步骤、预期与实际可观察行为，以及日志/截图/网络/其他产物的证据路径。移除 secret 和个人数据，保留关联 ID 与安全错误上下文。

说明可复现性，并区分确定性失败、疑似 Flaky、环境/准备失败和完成状态未知。只重跑足以确立证据的次数；绝不能通过无限重试或放大超时让结果消失。

根据证据而不是职责便利，将 `suspected_category` 设为 `implementation`、`spec`、`test`、`environment`、`baseline` 或 `unknown`。规划者负责最终归因，也可以将其分类为范围变化。测试者不得修改生产代码、重写预期行为、关闭 Defect，或覆盖既有 Defect/报告。修正应创建带 `supersedes` 的新产物。

严重度按共享审核严重度契约描述影响。只有证据支持时，才提供安全诊断或修复方向；不得指定推测性代码变更。

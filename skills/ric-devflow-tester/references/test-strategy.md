# 测试策略与可追溯性

起草或修订 DevFlow 测试计划时，使用本参考。

## 从风险和可观察行为出发

对每个 AC，识别用户/系统结果、失败影响、权威边界、保持行为、可能缺陷类别，以及能证明它的最低成本测试层级。当序列化、数据库约束、权限、进程边界、浏览器行为或部署接线无法在低层证明时，增加更高层覆盖。

创建稳定用例 ID，并包含前置条件、确定性数据、动作、预期可观察结果/副作用、清理、层级、自动化状态/所有者和预期证据。矩阵必须把每个 AC 映射到用例，同时把每个用例映射到 AC、兼容规则、风险或回归目的。

## 场景选择

按适用性覆盖：

- 正常和替代成功路径；
- 非法、缺失、null/空值、最小/最大、溢出、未知枚举和格式错误输入；
- 依赖失败、部分成功、恢复、取消和重复动作；
- 按动作/资源/所有者/租户授权，以及数据隔离；
- 并发/重复/乱序/幂等行为和事务竞争；
- 超时、有界瞬时重试、退避、资源清理和关闭；
- 旧客户端/数据/事件/配置，以及混合版本迁移/回滚；
- UI 的加载/空数据/错误/成功/禁用/无权限/离线、导航、焦点、响应式布局、可访问性、i18n 和极端内容；
- 注入/滥用/隐私/速率/资源边界，以及有依据的性能预算。

不要为了制造数量而加入无关清单用例。说明高影响风险为什么已覆盖，或为什么有意不运行。

## 确定性与环境

使用合成/最小化数据、唯一隔离、清理、受控时间/随机数/UUID/网络、有界轮询或框架等待，并记录版本/配置。避免依赖测试顺序、真实当前时间、未授权外部服务和大型快照。规划足以区分 Spec、实现、测试、环境和基线失败的诊断信息。

为每个必需行为标注验证权威层级：合成/Mock、本地真实边界、集成环境、live 服务或生产授权验证。记录每层的前置服务、配置、凭据/权限、可观察证据和不能证明的事项。低层结果只能证明其声明范围，不能替代 Spec 要求的更高权威边界。

若不可用环境对应的行为可以独立验收，测试计划应把它分为单独验证切片并将缺失条件报告给 Planner；其他切片可按各自门禁继续。若缺失条件是当前 Task 或发布结论不可拆分的必需前提，则退出条件必须为 `BLOCKED`，不得通过 Mock、Skip、无限重试或扩大超时伪造完成。

退出条件必须明确：必需通过项、允许接受的 P2 风险、历史失败差异、适用时的重复次数或 Flaky 阈值，以及何种情况产生 `FAIL` 或 `BLOCKED`。

## 复用仓库命令与执行资源

在现有测试计划的环境、自动化顺序与退出章节记录真实工具/运行时、包管理器、锁文件、配置、setup 命令，以及 affected、相关完整套件和目标冒烟的精确命令/范围；无现成入口就如实说明，不发明 DevFlow runner、不新增 CI。记录资源上限、隔离目录、端口/数据/fixture/快照所有者、命令超时、取消及清理方式。批准计划供执行者只读，修改 Oracle、环境或权限按原审核规则处理。

affected 选择依据精确 base/head Delta、AC 与实际依赖消费者，优先仓库已验证可靠的选择器。跨共享边界必须覆盖消费者；选择器缺失、不可靠、未知范围或结果无法解释时扩大到相关完整套件，不能只凭路径名猜测。空选择结果不等于 PASS，须核对覆盖并执行适当完整集合；不能通过排除失败用例获得“受影响测试通过”。G7 仍满足计划中的全部必需覆盖，G9 的命令单独声明。

依赖缓存只复用已有工具支持的能力，身份至少绑定平台/架构、运行时版本、包管理器版本、锁文件与相关配置。缓存缺失、损坏或任一身份变化则失效，按原仓库 setup 准备并记录结果；不安装未经批准的新依赖、不更换工具或放宽锁定。命中不是测试通过，setup 失败须如实 FAIL/BLOCKED，不能带着不明依赖继续验收。

复用测试服务须确认租约的配置、迁移版本、数据条件、健康、所有者及授权仍匹配，并记录实际准备与复用范围；改变任一条件使相关结果/租约失效。默认不共享可变数据库、测试输出、端口、fixture 或快照；无明确安全隔离就串行并使用原准备流程。只使用任务授权内可清理的本地资源，不创建常驻 daemon、不改变或停止用户服务，不将租约提示当权限。

测试命令默认合计最多两个并发进程组，实际 runner 内部 worker 和服务资源计入同一预算，服从 Planner 分配和更严格宿主/仓库限制。并行须无依赖且资源独立；一个 Task 的写入窗口仍只归一名作者。每条启动命令都收集退出码及结果，即使另一条先失败也不得早退丢失结果。取消/超时仅终止本任务拥有的子进程，随后 wait/reap 并清理自有资源；无法确认所有权时报告缺口，不杀未知进程。

## v2 存储与复核

原地维护 test-plan 与底部 Change Log；当前阶段展开细节，未来能力只记录依赖与验证边界。稳定用例 ID/独立修订，未变 Oracle 不因职责映射变化而复制整套计划。报告按原模板完整返回 Planner，保留失败/BLOCKED/not_run 与复现条件，由其原样追加 evidence。

独立验证不能退化为抄录实现者自测；相同输入下 Tester 自己的有效命令结果可引用，不要求 Planner 例行重复。新 SHA/环境/必要输入或覆盖缺口触发相称的补测，原报告的 tested_sha 不能改绑。

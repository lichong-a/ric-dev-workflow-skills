# 审核严重度与结论

审核者的结论只能是：

- `APPROVE`：没有尚未解决的阻塞发现，且所有必需证据均为当前有效。
- `REQUEST_CHANGES`：被审核对象可以修正，且至少存在一个阻塞发现。
- `BLOCKED`：由于目标、版本、SHA、权限、环境或证据不可用，无法完成可信审核。

不得使用“基本批准”或有条件批准。

| 严重度 | 含义 | 对门禁的影响 |
|---|---|---|
| P0 | 可利用的安全问题、数据丢失/损坏或严重生产风险 | 始终阻塞 |
| P1 | 必需行为不正确、重大回归或关键验证缺失 | 始终阻塞 |
| P2 | 具体的可维护性、可靠性、兼容性或一般风险 | 除非获授权所有者明确接受，否则阻塞 |
| P3 | 当前不存在发布风险的非阻塞改进 | 不阻塞 |

每条发现必须包含 ID、严重度、类别、精确位置、触发场景、证据、影响和安全的必要修复方向。不得把格式化器输出、个人偏好、推测性现代化或无关遗留技术债写成审核发现。

风险接受必须注明对应 P2 发现、接受权限主体、理由、范围、到期时间或复审条件、缓解措施和回滚方案。绝不能仅为推动门禁而接受 P0/P1。

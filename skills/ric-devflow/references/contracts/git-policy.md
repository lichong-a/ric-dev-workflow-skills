# Git、分支与并发策略

## 仓库事实优先

规划者按以下优先顺序确定目标分支和合并策略：用户明确指示、贡献指南、CI 触发规则、近期同类变更、upstream 跟踪关系，以及当前功能/发布实践。绝不能默认假设为 `main`。

记录：

```yaml
target_branch: ""
target_base_sha: ""
integration_branch: ""
integration_base_sha: ""
branch_strategy_source: ""
```

如果仍不能安全确定目标，应阻塞并询问用户。

## 分支拓扑与不可变基线

- 除非已有功能分支经验证就是续作集成分支，否则 Root Issue 的集成分支应基于实际目标分支。
- 所有依赖满足[有效依赖](workflow-state.md#有效依赖与恢复)（有有效证据的 `VERIFIED` 或 `DONE`）后，从最新已验证集成 SHA 创建各 Task 分支，并记录 `base_ref` 和 `base_sha`。
- 审核 `base_sha..head_sha`，而不是会移动的分支标签。
- 实现者绝不合并。规划者按 DAG 顺序和仓库既有合并策略执行合并，并在每次合并后触发增量测试。
- 不得强推或重写共享历史。

## 脏 worktree 保护

绝不能 reset、clean、丢弃、覆盖、自动 stash 或悄悄提交既有改动。记录脏文件及其与 Task 的重叠情况。若不存在重叠，并且条件允许，应从已知已提交 SHA 使用干净分支/worktree。若重叠工作无法在不造成丢失或错误归属的情况下隔离，则标记 `BLOCKED` 并说明需要用户作出的决定。

## 并发

只有在以下条件全部满足时才能并行工作：不存在 DAG 依赖；不共享公开契约、数据库或构建配置；写路径不重叠；每个区域只有一个写入者。只读侦察可以并行。共享遗留区域默认串行负责。

## 跟踪分类与授权

业务仓库默认提交 `.devflow/changes/<REQ-ID>/` 下的 `state.yaml`、`current.md`、`test-plan.md`、`evidence.md`，以及必要脱敏验收附件、正式快照与迁移索引；可引用满足身份和保留期限的现有仓库/CI 产物。不跟踪临时 Prompt、搜索输出、Diff 中间件、调试日志、临时报告、会话 ID/cursor/PID/机器缓存，它们放在 `.local/`。失败/BLOCKED/not_run 的正式结果仍须持久化，不能统统归为临时文件。

业务仓库的忽略规则示例：
```gitignore
.devflow/changes/*/.local/
```
与宿主已有规则合并，不能覆盖整个 `.gitignore`。用 `git check-ignore -v --no-index <path>` 检查实际匹配；`git ls-files` 检查已跟踪文件，ignore 不会自动取消跟踪。已跟踪临时文件只在明确授权和确认不丢唯一证据后用精确路径处理，敏感历史另行求解，不能用 ignore 掩盖泄漏。

**Skill 源码仓库**的 `.devflow/changes/` 排除规则仅用于防止提交演示产物，不能照搬到业务仓库。凭据和未经脱敏数据不得进入受跟踪产物或外部上传。

文件应当跟踪不等于获准 commit/push；宿主规则与用户授权分别控制提交、创建标签和远端发布。无 Git、证据不允许跟踪或无提交授权时，正式送审使用[生命周期](artifact-lifecycle.md)规定的不可变本地快照，明确仅本地可恢复；要求真实代码 SHA 的门禁仍不可伪造通过。

## 提交边界与两种身份

- 草稿连续修改，不为每次编辑/commentary 提交。
- 正式送审前固定有关文档版本；代码审核前固定完整候选提交（包含测试、生成物和必要文档）。
- 同一 Task 的生产与独立测试代码由各自作者在 Planner 安排的串行写入窗口完成；作者分别固定报告的真实 SHA 范围，Planner 汇集报告并交付完整候选 G5。G5 后的测试修正也须重新审核、集成和验证，不能混入先前受测 SHA。具体顺序见[测试代码交付](../shared/test-code-delivery.md)。
- 验收或状态切换时合并提交对应证据与状态，精确路径暂存，检查 staged Diff 和既有改动归属。
- 文档身份为完整 Commit SHA + 路径 + 对象 ID；代码证据仍为 `base_sha/head_sha/tested_sha`。
- 后续追加证据的提交不等于已受测代码候选，不需要文档记录保存自身提交 SHA。引用早先已存在的文档 Commit，避免自引用造成无限补提交。
- 新提交若只追加过程证据且代码树未变，也不能改写旧测试 SHA；由独立角色说明适用范围，宿主要求新 SHA 测试时照做。

迁移需额外保留持久基线标签、全文件索引及独立审核，详见[无损迁移](../shared/legacy-migration.md)。正常维护不得移动/删除基线标签；推送迁移结果必须在授权内同时发布基线引用并验证远端恢复，不能仅发布精简分支。

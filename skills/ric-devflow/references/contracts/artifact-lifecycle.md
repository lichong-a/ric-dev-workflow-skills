# 产物生命周期

持久产物是事实源，对话不是。布局与证据身份按本契约执行，角色权利不因文件合并而改变。

## 布局路由与稳定 ID

新 Root Issue 默认使用 [Compact v2](../shared/compact-layout.md) 与 [四文件模板](../../assets/templates/compact/state.yaml)，按进度创建文件，不预建空目录。既有 `schema_version: 1` 继续按原布局读取和运行；旧模板保留在 `templates/` 根目录。检测到旧版本目录时，Planner 只提出一次[无损迁移建议](../shared/legacy-migration.md)，未经授权不切换。

沿用 Root Issue `REQ-YYYYMMDD-NNN`、`TASK-NNN`、`AC-NNN`、`REVIEW-NNN`、`TEST-NNN`、`IMPL-NNN`、`DEFECT-NNN`、`DECISION-NNN` 或仓库已有不冲突的 ID。跨文件引用必须能定位精确对象，不能只写“最新版”。

## 持久文件路径

新写入 `.devflow/` 的文件（包括核心正文、报告、附件和 `.local` 中的交接材料）使用可随仓库迁移的路径。基准是当前交付所在的已确认业务仓库/worktree 根；无 Git 时使用已确认项目根。此规则适用于 v1/v2 的新内容，不改变 Schema、角色所有权或历史证据身份。

- 结构化文件/目录字段和正文中的仓库位置统一相对业务仓库根，使用 `/` 分隔。`repository.root` 写 `.`；`cwd` 写 `.` 或实际子目录，例如 `packages/api`。代码位置写 `src/service.ts`，产物引用写 `.devflow/changes/<REQ-ID>/current.md#SPEC`，快照和附件引用也带完整仓库相对前缀。不得写入本机盘符、UNC、用户主目录、`file://` 或工作树绝对路径，也不使用越出仓库的 `../` 冒充仓库内引用。
- Markdown 链接遵循文档相对寻址，例如同目录的链接目标 `current.md#SPEC`；链接目标相对所在文档，结构化 `path/ref` 相对仓库根，不混用解析基准。历史 `current.md` 等 Root 内短引用继续按原布局解析，不因新规则改读为仓库根文件；歧义须核对原身份，不能猜测。
- 宿主工具所需的仓库/worktree/Skill 绝对位置仅在会话上下文与调用参数中解析，不复制到持久产物。仓库外工具或 Skill 用已确认的资源名、版本或来源 SHA 加资源内相对路径记录在现有环境/说明字段中；可引用稳定外部产物 URL，不把外部资源伪装成仓库内 `path`，也不新增机器路径状态字段。
- 命令优先从明确的相对 `cwd` 使用相对参数执行；工具要求绝对 `workdir` 时仅在调用时展开。外部工具参数需要本地根目录时使用已说明来源的会话变量，记录其逻辑用途和必要版本，不持久化本机展开值。日志优先配置为相对路径输出；确需规范化输出时由作者在发布前注明路径替换规则，保持命令、退出码和有意义结果，不把处理后的文本冒充逐字原始输出。URL、接口路由、测试输入与符号链接目标等原始业务值不按本机路径批量替换。
- 各作者在返回/发布产物前完成路径检查，Planner 写入前核对引用能从相应基准定位且正式证据不依赖 `.local`。不符合规则的新报告交回原作者修正，Planner 不改写角色载荷。已发布报告、原始快照与迁移保全字节维持原样；历史绝对引用经核验后可在新记录中补充相对定位及来源身份，不能全局替换历史或重新计算哈希后声称原批准仍绑定同一对象。

## 草稿、发布与取代

- 草稿可连续原地编辑，不为内部预检、commentary 或每次保存制造正式修订或提交。状态可索引草稿，但不能把它作为有效 Gate 证据。
- 正式送审前固定对象修订与不可变身份：Git 完整 Commit SHA + 路径 + 对象 ID；无 Git、不能跟踪或没有提交授权时保存不可变本地快照及内容哈希，注明仅本地可恢复。代码门禁所需 SHA 不能用文档哈希替代。
- 一经交给独立 Reviewer 或产生正式结论，被审内容即已发布；被拒绝或阻塞的版本也须可逐字恢复。v2 的固定正文文件可以继续修订，历史由 Git 或快照冻结；v1 已发布的旧路径不可覆盖。
- 每个 Task 独立修订。局部修改不递增无关 Task/测试用例版本，不复制 Root、Profile、Decision 或整套矩阵。
- 审核、测试、实现、Defect 的已发布记录不可修改；修正由原职责作者发布新 ID/版本与 `supersedes`。v2 在 `evidence.md` 追加，v1 新路径发布。历史结论始终保留原绑定。

## 有效性而非父文件版本连锁

| 证据 | 原绑定始终保留 | 当前使用要求 |
|---|---|---|
| Spec 审核、用户批准 | Spec 对象修订与文档身份 | 受影响行为变化重开 G2/G3；含义未变按变更控制记录适用性 |
| 测试审核 | Spec、测试计划对象修订与身份 | Oracle/权限/环境边界变更重开受影响 G4；纯职责映射局部复核 |
| 代码审核 | Task、Spec、完整 `base_sha..head_sha` | head 或相关行为变化需新的绑定审核，可按风险增量复审 |
| 测试报告 | Spec、计划、环境、完整 `tested_sha` | 仅证明原输入；代码、环境、必要输入改变需按影响补充验证 |
| 发布审核 | 集成 SHA、证据集 | 当前集成 SHA 和覆盖必须一致，不能用后续记账提交冒充受测候选 |

同一未变对象与必要输入直接引用原批准，不重复生成适用性记录。跨对象沿用时说明旧/新对象、精确 Delta、未受影响范围和复核依据；纯过程/EDITORIAL 的无需单独审核条件按[变更控制](change-control.md)执行。不得篡改旧载荷、空写“继续有效”或把旧 `tested_sha` 换成新 SHA。

## 持久化与恢复

各角色独立生成完整载荷；Planner 原样追加到账本，仅承担传输，不获得作者或批准权。作者发现错误时另发取代记录，不由 Planner 改写。失败、阻塞、未运行项同样属于正式证据。

先写完整证据、验证 ID 和载荷，再更新状态索引。中断恢复先核对记录 ID：同 ID 同载荷复用，不重复追加；同 ID 异载荷阻塞并向作者求解。未完成写入不得被状态引用；临时草稿可重建，已完整发布的记录不得覆盖。正式证据不能只依赖 `.local/`；可复现条件不足时保留必要脱敏附件。

只有 Planner 可以更新 `state.yaml`。v2 状态只保留当前索引；事件、历史状态、Finding 处置和适用性结论进入账本。矛盾证据未解决前，对应 Gate 保持未通过。

# v1 到 Compact v2 的无损迁移

只在检测到旧布局或用户要求迁移时加载。旧布局包括 `schema_version: 1`、`spec-v*`、`tasks-v*` 等；检测不是迁移授权。此流程只转换容器，不重新授予产品批准、测试 PASS 或失效 Gate。

## 一次建议与权限前检

先查已有 `attachments/migration-v1.md` 或已记录迁移检查点，按索引恢复；没有时做一次盘点建议：旧文件规模、state 指向的当前对象、迁移范围、未解决冲突和所需权限。不要重复展开整个版本树。

只读仓库、其他活跃写入者或该 Root Issue 授权不充分：只给具体建议，继续按 v1 运行，绝不切换或清理。必须分别明确本地迁移、将指定旧内容纳入 Git 基线并创建持久标签、删除已核验工作树副本、以及是否发布到远端的授权。一次明确涵盖这些动作的迁移批准即可，不按文件重复询问；迁移授权不等于推送授权。无 Git 或宿主不许跟踪这些内容时，默认保留 v1；新 Root 可用 v2 本地快照，不偷偷以临时备份代替 Git 迁移基线。

## 1. 全源盘点与基线

停止该 Root 的其他写入，在授权范围内枚举全部源文件（含隐藏、非标准名称、二进制、受跟踪、未跟踪和未提交内容），保存路径、文件类型/模式、内容 SHA-256、Git 状态及有效引用；核对作者、版本、SHA、supersedes、外部来源和未知字段。符号链接按链接本身保全，不遍历出授权边界；Git LFS、子模块、外部 CI 内容必须另核对真实字节和持久可恢复性，指针不是已保全内容。

用原生 Git 精确路径建立包含全部需保全字节的基线提交，不能仅依赖当前 HEAD 或只枚举已知模板。逐项审查敏感数据与所有权；无法安全纳入的未提交文件、冲突、LFS 内容或外部证据必须先解决保全问题，期间保留旧目录，不擅自 commit 用户修改、不泄露 secret。不允许用“忽略该文件”通过完整性检查。

在基线 Commit 上创建持久标签 `devflow-migration/<REQ-ID>/v1-baseline`。同名标签已存在时验证但不移动/覆盖，选择首个空闲 `v1-baseline-2`、`-3` 等，并把实际标签和完整 Commit SHA 写入索引。标签应可达且保存到关闭后；禁止正常清理时移动或删除。盘点到固定基线之间若内容变化，重新核对差异，不能静默吸收新增内容。

## 2. 隔离生成候选

保持业务工作树的 v1 state 入口和所有旧文件不变。在隔离 worktree 或 `.local/` 中构建迁移候选；正式审核前候选必须成为可读取的不可变 Git 提交/树，不能仅引用临时草稿。Planner 负责 current/state/索引及原样转录；Tester 编写或核验迁移后的测试计划，Reviewer 不参与改写。

依 state、批准、取代和失效链选出当前有效正文，不能取最大版本号。合并目标、非目标、AC、UI、保持行为、Task/依赖、测试 Oracle、权限、预算、开放问题、延期和跨阶段关系。拒绝版本只作为历史，不能重新激活其中的要求。冲突明确保留两侧来源，未解决前不声称可切换。

当前有效和处理开放问题必需的审核/测试/实现/Defect 载荷原样进入 evidence；其他历史原文留在基线，不把所有版本复制成另一本巨大账本。不改旧 ID、SHA、Verdict、字段或历史引用。过期批准仍标为过期，未运行保持未运行；迁移不使旧门禁重新通过。

## 3. 一次性迁移索引

候选包含受跟踪的 `attachments/migration-v1.md`，不另造状态数据库。顶部记录授权范围、实际基线标签/完整 SHA、基线是否仅本地、盘点检查点、冲突及审核引用。逐文件表至少包含：

| 旧路径及类型/模式 | 基线 Commit 与内容哈希 | 逻辑 ID/未知内容 | 处置 | 新位置或历史恢复位置 |
|---|---|---|---|---|
| 每一个源文件独占一项 | 完整 SHA + SHA-256 | 原 ID、扩展字段和冲突 | 当前合并 / 原样证据 / 仅历史 / 待解冲突 | 新章节/记录；或基线 SHA:旧路径 |

逐项列全，不用“其余见 Git”掩盖遗漏。当前条款和关系对应到新 ID/章节，所有旧文件都有字节恢复来源；未知字段不能只写“已忽略”，须保留具体值/原文的基线位置并说明是否影响当前行为。目录状态和开放问题仍由 state/evidence 索引，不复制全索引进 state。

## 4. 完整性与独立审核

先逐项从实际标签解析的 Commit 取回旧内容，比较原始字节、类型/模式与哈希；验证源文件集合无新增/消失/变化，当前条款与关系无遗漏、原角色载荷逐字一致、引用通过索引可解、无未解决冲突、临时路径不是唯一证据。对语义的逐项核对不能只用文件数或哈希代替。

将精确迁移候选 Commit、基线 Commit/标签、索引、源范围和测试计划作者证据交给独立 Reviewer，以 `BASELINE_REVIEW` 模式明确限定“迁移内容与引用完整性”。不增加审核模式或 Gate，不要求重审无关产品行为。Reviewer 返回原 Review 载荷；Planner 原样追加。该 APPROVE 只证明迁移转换，不关闭开放 Finding/Defect，也不激活过期 G2/G3/G4/G5–G9。

## 5. 最后切换与故障恢复

批准后再次比对源盘点、候选身份和索引；源内容变化或审核对象变化就暂停，更新对应差异与独立审核，不覆盖活跃工作。以宿主安全事务/隔离工作树应用已审候选。仅批准记录追加与切换事件可以在候选外补入，任何正文/索引变化均需复核。

先使已核验 current/test-plan/evidence/attachments 完整可读，再最后切换 state 到 v2。v1 与 v2 同名文件（尤其 state）必须保留旧字节在基线，不得在审核前覆盖活动入口。切换失败时保留/恢复原入口，从检查点继续；部分 v2 文件不能被当作迁移成功。只有新入口完整核验后，才按索引列出的明确旧路径逐个移除已保全副本；不能递归删除整个 `.devflow`，不能删除新核心文件或未盘点文件。迁移并不授权清理业务代码。

清理失败保留剩余旧副本与检查点，无须重新复制整个历史；旧副本只作为历史，不形成第二套当前状态。最终事件记录迁移审核、实际入口和剩余清理项。没有完整性/独立审核/切换证据，不写迁移完成。

## 发布、克隆与恢复

未发布明确标注“迁移基线仅本地可用”。有既有推送授权时，将分支和实际基线标签一起发布；优先宿主支持的原子推送。不支持原子推送时先标签、验证基线可取，再分支；任一步失败均不声称远端迁移完成。通过隔离 fetch/clone 取得远端标签并逐项恢复旧字节，不能仅用本地已有对象或 `ls-remote` 代替恢复验证。不要仅发布精简分支，也不要在 squash 后遗漏保留标签。

以下为原生 Git 用法示意，替换成索引中已核验的实际值，不添加默认远端/分支：
```bash
git show <baseline-full-sha>:<old-path>
git show <doc-full-sha>:<current-path>
git fetch <remote> refs/tags/<actual-baseline-tag>:refs/tags/<actual-baseline-tag>
git rev-parse <actual-baseline-tag>^{commit}
git push --atomic <remote> <branch> refs/tags/<actual-baseline-tag>
```
需要落地恢复文件时，选择安全新路径，不覆盖当前正文。浅克隆先补取索引记录的标签；最新 ZIP 不承诺包含历史原文。不得在正常维护中删除/移动迁移基线标签。

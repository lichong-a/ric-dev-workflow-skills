# 子代理思考参数兼容

仅由主会话在首次确定某角色的思考参数、相关能力变化或明确的参数不兼容失败时读取。普通续作复用当前有效协商结果，不重读厂商资料；只读取下表中当前接入方的必要文档。本参考不创建 Root，不改变 Gate，也不是模型选择器或安装器。

## 协商对象与证据

保持当前已选定的模型、供应商、接入端点、权限及用户预算。主会话 Planner 使用现有设置；未被用户指定设置覆盖时，Reviewer 偏好 `high`，Tester/Implementer 偏好 `xhigh`。这些是协商意图，不是写入原生模板的固定参数；不能把提示词里的“多思考”当成已设置真实等级。

先核对当前工具 Schema、宿主声明的模型能力、接入协议和实际生效配置。宿主/网关可能只暴露供应商能力的子集；模型目录只有 ID 而没有能力字段时，不据此推断等级。只读当前必要配置且不输出凭据，不递归扫描用户目录。官方文档用于解释当前接入方式，不能用厂商或型号字符串推断本会话接受的值。

配置优先级须按宿主核实。尤其 Codex 自定义角色文件中的 `model_reasoning_effort` 可覆盖创建参数：若旧安装仍固定错误值，不能声称改一次调用参数即可修复；沿原安装/配置冲突规则报告，不自动改用户文件或用通用代理替代。发布模板不设固定模型/等级，但既有 `[agents]` 默认或用户定制仍可能影响最终值，省略字段不保证清除了错误覆盖。

## 选择与有限纠正

1. 先检查该角色已有实例；可恢复的实例继续使用原模型和有效设置，不为调整偏好重建。需要改变现有实例参数时，仅使用宿主真实支持的更新能力；不支持则保留已可用配置并说明，不能假称更新生效。
2. 首次创建时，原请求值在当前接入层可用就保留；存在明确的接入层别名/映射时遵从该映射，同时记录请求值与实际值。不能用通用映射覆盖宿主已声明的语义。
3. 原值不支持且没有明确映射时，只从已确认可用的集合中选择：`xhigh` 缺失而 `max` 可用则映射为 `max`；`max` 缺失而 `xhigh` 可用则映射为 `xhigh`；二者均不可用且 `high` 可用则取 `high`。`high` 原值可用时不升为更高档；其他值不猜排序，采用有证据的等价映射或进入下一步。记录强度调整，不宣称不同厂商效果相等。
4. 仅有 thinking 开关、预算或默认模式时，保留已经确认可用的思考模式与预算/动态默认，不编造数值预算、不擅自禁用思考或增加费用上限。仅当调用 Schema 支持对应控制时传参；原生 API 字段不能直接塞进 Agent 工具。没有可控等级时，确认继承/默认配置可用且不会再次携带错误覆盖后才能省略等级；否则停止受影响交接并列出能力缺口。
5. 创建失败先检查错误指向的字段、允许值、实际生效配置以及启动事件。只有明确归因为思考参数不兼容、且宿主确认任务未执行时，才按新的能力证据纠正重试。同一交接最多两次纠正重试（不含首次调用），每次必须有新依据，不能重复已失败的参数组合。没有新依据、次数耗尽或错误类别改变时停止该适配循环并交回对应恢复流程。
6. 已返回实例 ID 但模型初始化失败时，先核对其生命周期；能在原实例修复就继续，确需替换时仍遵守[实例生命周期](agent-lifecycle.md#复用与受控替换)的停止与替换条件。已启动业务动作、网络超时或是否启动未知时，先查询/等待/恢复原动作，不再次提交相同工作。业务 FAIL/BLOCKED 不是思考参数不兼容。

认证、权限、禁用、来源冲突、缺少角色、网络、并发额度等错误，按[加载与调用核验](../bootstrap.md#文件加载调用分别核验)分别处理；不会通过降思考等级、换模型、改全局配置或重启来掩盖已知原因。

## 当前接入方参考

以下是查证入口与需区分的能力形态，不是固定支持矩阵。核验日期：2026-10-06；实际值和可用字段以当前宿主、接入协议及模型能力为准，不冻结具体型号清单。

| 接入方 | 需要核对的控制形式与边界 |
|---|---|
| OpenAI / Codex | [子代理配置](https://learn.chatgpt.com/docs/agent-configuration/subagents)：客户端与所选模型共同限制等级；核对角色文件、创建参数、全局默认与继承的优先级。 |
| Anthropic | [Effort](https://platform.claude.com/docs/en/build-with-claude/effort)：effort 与 thinking 模式分别核验；`max`、`xhigh` 的支持不能由厂商名推断，`adaptive` 不是 effort 值。 |
| Google | [Gemini Thinking](https://ai.google.dev/gemini-api/docs/thinking)：区分 `thinkingLevel` 与 `thinkingBudget`；不同时乱传、不把离散等级换算成臆造预算。 |
| 智谱 / GLM | [Thinking Mode](https://docs.z.ai/guides/capabilities/thinking-mode)：原生 thinking 模式与宿主的 effort 枚举分别核验；只有实际接入层支持 `max` 时才进行 `xhigh → max`。 |
| DeepSeek | [Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)：不同协议的 effort/thinking 字段及接入方别名映射优先于通用回退；已接受并映射的 `xhigh` 不改成另一个值。 |
| 通义 / Qwen | [Responses 参数](https://docs.modelstudio.console.alibabacloud.com/en/model-studio/qwen-api-via-openai-responses)：核对协议中的 `reasoning.effort`、思考开关和模型能力；OpenAI 兼容格式不表示支持相同枚举。 |
| xAI | [Reasoning](https://docs.x.ai/developers/model-capabilities/text/reasoning)：按实际能力确认 effort 可调或固定/默认思考，不将其他厂商的档位整组移入。 |
| 其他或未知接入方 | 使用已暴露的能力与当前官方协议；无法确认支持的参数就沿已验证继承/默认路径或报告缺口，不试遍型号或猜测字段。 |

## 复用与证据

协商记录只保留必要的宿主/主会话、原生角色及实际模型身份、供应商/接入协议与非敏感配置身份、请求值、有效值、支持依据、重试次数和真实返回。放当前会话；已有 Root 时可缓存于 `.local`，无 Root 不建目录或正式 Schema。不要记录令牌、完整连接串或推理内容。

模型、接入方式、有效配置、工具 Schema、支持能力或主会话变化时使相关协商缓存失效；已有实例不因此自动被销毁。重新核验必要范围，保留原任务进度和已完成工作。成功请求只证明该次可用，不能把历史成功当本次调用证据；仍失败的结果与解除条件按原证据契约记录，不能改写成 PASS。

# 子角色实例的生命周期

主会话首次实际派发前读取“职责、实例与推进条件”；普通交接只核对“复用与受控替换”，遇配额、取消或独立 READY 波次时再读相应章节。已读且条件未变的规则复用，不首次展开其他平台或后续阶段。主会话始终是 Planner；本参考不增加业务角色、Gate、状态或报告 Schema。

## 职责、实例与推进条件

固定的是 Reviewer、Tester、Implementer、Researcher 四种逻辑职责及权限边界，不是四个永远不变的实例 ID，也不要求四个线程常驻。默认每种角色按需保留一个可复用实例；运行时 ID 可因安全回收、恢复或受控替换变化。临时并行实例仍属于原职责，只有主会话可以调度，任何子角色不得派生代理。

主会话维护逻辑角色与实际 agent ID/恢复句柄的映射，记录宿主与主会话、规则来源、权限、当前 Root/Task/动作、工作区/精确 SHA、生命周期、原结果保全位置、取消范围及回收/替换原因。它是会话调度信息，不是新的正式 Schema；已有 Root 的 `.local` 可缓存相关投影，无 Root 不建目录。保留旧新实例的交接关系，不能让角色名或相同 task_name 冒充同一实例，也不能因缓存丢失直接认定实例已消失。

首次实际派发前，以真实 Schema、配置、实例清单或宿主反馈确认：能取得动作结束与完整结果；所需原生角色可按需调用；当前额度及资源释放方式至少允许串行推进。已知容量能保留所需线程，或能安全释放后恢复/替换，均是可行路径。没有恢复接口本身不阻塞；没有任何已确认推进路径则在派发前说明缺口，不先占满额度再无效等待。没有容量计数接口时不编造剩余额度，利用可观察生命周期、配置及明确拒绝核对边界；未知事实不作成功保证。

## 复用与受控替换

每次交接核对当前对象、权限、独立性和宿主状态。空闲/已完成且可恢复的实例优先使用真实 ID 继续；不得为文件、用例、报告章节、普通返修或思考偏好新建实例。同角色忙碌时默认排队，只有“有限扩容”全部条件满足才并行。恢复已关闭实例也可能重新占用额度，须先核对容量。

只有以下原因可进入替换：宿主没有恢复接口、单实例不可恢复、容量回收后不能恢复原 ID、已证实权限/独立性无法沿用，或旧工作已取消而用户另行授权了不受取消范围约束的独立新工作。必须先满足全部前提：旧动作已结束、完整结果或取消检查点与已发生副作用已保全、旧写入窗口结束、下一动作获准、职责/权限仍匹配。再解除旧活动绑定，创建同职责替代实例；只有创建/恢复下一实例会超出宿主或本工作流上限时，才必须先按下节安全释放。未释放的旧实例即使退出活动绑定，也继续计入实际打开总量和每角色上限，不能靠改映射隐去占用。不把已完成动作重新执行一遍，不同时保留两个未区分的写入所有者。

新 Reviewer 接收必要审核谱系，对本次审核对象执行契约要求的完整审核，不能声称是原实例的增量复审；历史已完成且仍有效的 Gate 只核对适用性，不机械重跑整条审核链。新 Tester/Implementer 从原 Task、精确候选、已保全结果和未完成检查点继续，不能把恢复变成新 Task 或新一轮规划。旧报告的作者、ID、SHA 和结论不改写。

切换 Root/仓库时重新绑定批准、路径、环境与精确 SHA，不沿用旧授权或结论。Root 关闭和上下文压缩不清空逻辑职责与证据关系；容量允许且实例可用时复用，资源回收不等于丢弃逻辑归属。超时、结果丢失、取消未完成或生命周期未知时，先查询/等待原动作并取回完整结果，不能重派未知动作、先关闭唯一结果来源或用替换掩盖证据丢失。 查询不得用会改变生命周期的恢复、继续或重新派发代替；`not_found` 只表示当前接口未找到目标，不单独证明旧动作已结束或额度已释放。

## 配额与安全回收

区分业务并行数、命令进程数、打开线程数及仍保留的历史。宿主若按打开线程计数，完成或停止执行不必然释放额度；中断不等于关闭，关闭不等于删除历史。创建和恢复前均核对实际宿主限制、已打开实例和可观察的其他占用，不自动提高用户的线程上限。

容量不足时只处理本工作流拥有、动作已经结束、完整结果/检查点及副作用已保全、没有活动写入者的闲置实例。先回收无后续动作的临时扩容实例，再选近期无需要的默认闲置实例；同等条件优先最近最少使用者。只调用宿主真实支持且能释放所需资源的挂起、卸载或关闭能力，保留报告和历史，核对释放回执或更新后的容量后才再次派发。不能删除会话历史、清空工作区、关闭其他任务的代理，或把“已发送关闭请求”当作已释放。

四种默认职责不要求同时打开四个实例。若 Reviewer/Tester/Implementer/Researcher 四个默认实例均仍打开，已占满工作流四实例上限；下一次会新增实际打开占用的创建、恢复或临时扩容前，先保全并安全回收一个已结束闲置实例，取得释放证据，不能在四个之外再开第五个。可继续的已打开实例仍优先复用。Researcher 只读也计入打开总数，事实调查、例行总结或等待本身不授权扩容；无安全回收/恢复路径或生命周期未知时只停受影响动作，不重派、不修改用户上限。

每次因配额被拒的交接最多一轮有界回收和一次重新派发。一轮只处理已核验的有限候选；仍不足、回执不明、没有安全释放接口或只有外部实例占用时，停止重复创建，等待真实资源变化或报告精确阻塞。没有正在进行的释放/结束事件可等待时，不把静态占用包装成无限等待。配额恢复与思考参数纠正分别归因、各守预算，不能互相重置计数来无限重试。

配额为 1 时可依次保全并释放前一角色，再恢复/替换下一角色；配额为 2 时按实际下一动作释放必要的闲置实例。恢复原 ID 不可用但受控替换条件成立时仍可推进。所需生命周期、保全或释放条件无法确认时只停受影响动作；不把不足的权限或容量解释为可由 Planner 代写实现、审核或测试。

## 取消的作用范围

记录用户取消的是动作、Task/Root、角色后续执行还是全部自动化，以及它关联的实例；取消不能简化为“这个角色永远不可用”。“停止”“不要继续”默认针对当前正在执行的工作；只有歧义会影响下一动作时才询问。取消请求发出后仍要确认实际动作停止，并保全已发生副作用和恢复检查点。

| 已确认的取消范围 | 后续处理 |
|---|---|
| 当前动作或 Root A | 不恢复、重试或通过替换继续 A。用户后来明确授权独立 Root B，且旧实例已停止、检查点/副作用已保全时，可为 B 受控创建同角色替代实例；无需要求先恢复 A。不能仅改任务名，把 A 的未完成工作伪装成 B。 |
| 该角色的后续执行 | 保持该角色停止，直到用户明确解除；新 Root 请求本身不自动解除此范围的禁令。 |
| 全部自动化/当前主会话工作 | 所有相应派发保持停止，等待用户明确恢复；不通过新实例或子会话绕过。 |

用户取消的具体实例不能假称可自动恢复。若宿主拒绝继续该 ID，保留该实例的取消事实；合法独立新工作按上表创建替代者，旧任务保持取消。生命周期未知时不创建替代者，也不为确认取消去重跑旧动作。

## 有限扩容

默认每角色一个实例。仅当已批准且冻结的 DAG 中有两个独立 READY Task，工作区、契约、数据、构建、端口、fixture、输出和快照均隔离、当前权限与资源足够，并能说明减少哪段独立任务排队时，主会话才可增加一个临时同角色实例。收益没有依据或存在冲突时串行，不为并行改 DAG，也不把预期收益写成实测提升。

窗口按原 Task DAG 的拓扑顺序、再按稳定 Task ID 选择，并核对预计实际写集和冲突串行流；同流不并发，跨流不建立新的依赖图。研究缺口本身不能满足两个独立 READY Task 或收益条件，Researcher 与其他角色遵守同一总数、取消和结果保全边界。

同时最多两个独立 Task、每角色最多两个打开实例、整个工作流最多四个打开实例，服从更严格的宿主/仓库限制；外部占用也会减少实际余量。同一时刻最多一个仍打开的临时扩容实例，已完成但未释放的也计入；释放旧扩容实例后才能为另一职责扩容，不把每角色上限相加当作工作流总额度。每次交接一个完整 Task，同 Task 单一写入窗口；不得为文件、用例或报告章节扩容，不递归派生。

用实际 ID 区分默认与临时实例，禁止依赖重名路由。宿主若要求唯一 task_name，临时实例附当前 Task 的稳定标识，后续仍用真实 ID 继续，不用改名制造新实例。扩容实例优先承接同一批准波次后续工作；波次结束且无后续动作时，保全完整结果后安全回收，回到默认布局。不能安全释放时保留可观察占用并停止再扩容，不隐瞒累计线程数。

Tester 命令进程组仍默认合计最多两个，嵌套 runner 计入资源预算；命令并行与代理扩容分别控制。集成按 DAG 串行，每个新集成 SHA 仍取得 G6。盲评的上下文独立性缺口可按前述条件替换，但不单独构成扩容理由，不谎称已遗忘旧上下文。

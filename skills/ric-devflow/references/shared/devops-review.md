# DevOps 与基础设施审核

涉及 CI/CD、容器、部署、IaC、运行时配置或运维变更时，加载本参考。除非另有单独明确授权，实际 apply/deploy 始终不在范围内。

## 构建与供应链

使用固定工具链、锁文件、仓库 Wrapper，并让本地与 CI 执行同一套规范检查。不得用无条件成功掩盖失败。CI 权限必须最小化；不可信 Fork 或输入不能获得生产 secret 或高权限 Token。按仓库策略把第三方 Action/插件固定到可信的不可变版本，并推广同一个不可变产物。

容器应使用明确稳定的基础镜像；适用时采用多阶段构建和最小运行时；以非 root 身份运行；配置 `.dockerignore`；外置 secret/配置；支持优雅停止与兼容的健康检查。不得把 secret 放入 `ARG`、`ENV`、镜像层、日志或产物。

## 声明式基础设施

Terraform/Ansible/Helm/Kubernetes 变更应保持声明式、可审阅、幂等且范围狭窄。运行 format/validate 和 plan/diff，但不得自主 apply 生产变更。有状态资源替换/删除、权限扩大、缩容、DNS/证书变更和生产数据路径都属于必须另行批准的边界。

## 部署安全

记录混合版本兼容性、迁移/配置顺序、readiness 与 liveness 的区别、容量/资源限制、失败回滚/前滚修复、Feature Flag 生命周期、健康验证和所有权。避免使用 `latest`、可变产物或无界上线假设。

## 可观测性与 Runbook

审核请求/Job/消息关联、结构化脱敏日志、吞吐/错误/延迟/饱和度指标及其有界标签、能映射到运维动作的告警，以及迁移和定时任务的成功/失败/积压/耗时可见性。复杂恢复或重放必须有经过测试的 Runbook。

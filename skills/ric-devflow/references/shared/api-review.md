# API 与契约审核

创建或修改 HTTP/RPC/GraphQL/库导出、事件、Webhook、配置或序列化契约时，加载本参考。

## 定义完整契约

明确字段类型，必填/可选/null 的区别，默认值、约束、未知值、分页/过滤/排序语义、稳定顺序、幂等性、认证与授权、成功与错误模型、限流、超时、版本策略和可观测标识符。真实失败不能包装成成功响应。

在边界验证所有外部输入，在权威的服务/领域/数据层执行业务不变量。授权必须覆盖动作、资源、所有者和租户，不能只判断是否已认证。

## 兼容性

- 滚动升级期间优先使用新增字段和容错读取方。
- 区分省略、null、空、零和默认值；保持既有语义。
- 考虑已有生成客户端、存储载荷、重放事件、旧消费者、缓存、签名和文档示例。
- 破坏性行为必须显式版本化，并提供迁移和退役路径；不得伪装成内部重构。
- 将契约测试绑定到已批准 Schema；条件允许时，让测试跨过真实传输/序列化边界。

## Webhook 与消息

认证发送方；对原始规范化载荷验证签名；防止重放；对副作用去重；处理重复和乱序投递；返回符合协议的重试信号。不得记录 secret 或完整敏感载荷。回调/URL 抓取必须限制协议、地址、重定向、DNS 重绑定、响应大小和耗时。

## 审核证据

必须提供 Schema/diff、受影响生产者与消费者、兼容矩阵、测试映射、上线顺序及回滚/前滚修复方案。仅凭代码声称“调用方不受影响”并不充分。

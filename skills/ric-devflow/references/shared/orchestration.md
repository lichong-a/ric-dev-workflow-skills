# 编排与交接

从第一次向 Reviewer、Tester 或 Implementer 委派开始使用本参考，包括仓库基线和正式 Spec 之前的只读调查。持久产物是事实源，对话只传递当前动作和不可变身份。

三平台统一采用主会话 Planner 单层调度：主会话直接加载 Planner Skill，委派 Reviewer、Tester、Implementer 的单一角色动作；最后 Task 可按[条件批量执行](../contracts/gate-policy.md#最后-task-的-g6-与-g7-条件批量执行)在一次 Tester 调用内先 G6、通过后 G7。不创建 Planner 子代理；三个子角色不得再启动任何代理。Task 内步骤/测试用例/审核维度不变成子 Task。完成交接或报告精确阻塞后返回同一主会话 Planner，不重新跑一套需求规划。DAG 粒度与冻结例外只按[Task 规则](task-decomposition.md)执行。

范围内开发请求经 ric-devflow 入口准备后由主会话进入 Planner；独立角色仍须用户显式调用或 Planner 精确委派。前提具备时主动按当前宿主真实工具 Schema 派发或恢复对应角色，不等用户补一句“使用 subagent”。宣布下一步、写出交接或列出角色名不等于实际调用；获得结果后按门禁继续推进。用户已授权的范围和操作不重复询问，但缺少的 G3 产品批准、权限及其他仍适用的授权不能由自动派发补造。

## 按需派发与会话复用

同一主会话固定三个角色槽位：Reviewer、Tester、Implementer 各一个有效子代理，首次真正需要该角色时才创建；主会话自身是 Planner，不占子代理槽位。跨 Task、返修、报告、Root 关闭和同主会话内的新 Root 均复用原实例，不预启动暂时无工作者，不按文件、用例、维度或轮次扩容。

主会话维护角色到实际 agent ID/宿主恢复句柄的映射，绑定宿主与主会话身份、规则来源、职责/权限、生命周期、当前 Root/Task/仓库/工作区和最后检查点。映射以会话上下文为主，已有 Root 的 `.local` 可缓存该 Root 相关投影；不建独立账本或正式 Schema，无 Root 不为缓存创建目录。固定角色名或相同 `task_name` 不是同一实例的证据。

每次交接先核对映射与宿主状态：已创建且空闲/完成的角色用实际 ID 调用已暴露的继续、消息或恢复接口；忙碌时排队，不并发塞入另一个 Task，也不新建同角色副本。结果丢失、超时或生命周期不明时先查询/等待原动作。宿主不支持恢复时报告缺口并停止相关交接，不通过连续新建绕过。普通完成或上下文压缩不清空映射；恢复时先用宿主记录和当前证据重建绑定，不因缓存丢失认定实例不存在。

切换 Root/仓库/工作区前确认上一动作已结束，重新核对当前输入、精确 SHA、允许/保护路径、权限和必要批准，仅交接当前动作的最小材料；旧 Root 的授权、环境、证据与判断不能自动沿用。角色发现收到的身份与当前动作不符时先返回差异。只复用上下文和有效能力，不把前次审核/测试结论应用到新对象。

仅在实例确实不可恢复，或已证明职责、权限、独立性无法继续满足时替换该槽位。先记录原因并确认旧实例停止，收回旧写入窗口、解除旧映射后才能创建替代者；保全审核谱系并对新 Reviewer 执行相应完整复审。用户主动取消的实例/任务保持停止，只有用户明确恢复才继续，不能自动重建绕过取消；生命周期未知不能替换。模型偏好调整、普通返修、收尾或“多一个视角”都不是替换理由。

独立 READY Task 满足[并发条件](../contracts/git-policy.md#并发)时仍可由不同角色交错推进，默认最多两个 Task；需要同一角色的动作排队。Tester 命令进程组默认合计最多两个，服从更严格限制，进程并行不新增代理。需要盲评时在原 Tester 的适用动作中隔离 Oracle；已有上下文确实污染必需独立性时按上述证据与停止条件替换该槽位，不能另加执行者或谎称已遗忘上下文。

首次确定子代理思考参数、相关能力变化或明确参数不兼容时，主会话按[思考兼容](reasoning-compatibility.md)核对并协商；同模型下调整参数，原实例可用就继续，不能为适配创建探测代理或改变模型/权限。

首次及后续交接均按[加载与调用核验](../bootstrap.md#文件加载调用分别核验)确认本次目标：复用当前会话有效加载信息，以已获授权的必要交接验证实际调用，不额外派发探测代理。文件与配置正确但目标未加载或当前会话无调用能力时，及时提醒用户重启 Agent、在同一项目重新调用 Skill，并附恢复信息；其他失败按具体原因处理。单个角色成功不代表其他角色可用，已启动动作不因核验失败而重复提交，已启动子角色只回交宿主。

会话复用与工作区复用分别核对。同一 Task 的实现、独立测试代码和普通返修默认在同一 detached worktree 串行交接，不随作者或会话切换新建分支/worktree。只读角色只取得精确对象的读取位置。需要准备、换基线或回收工作区时才加载 [Git 策略](../contracts/git-policy.md)对应章节；先保全所有已发布候选，再允许换基线，不能让被拒绝的旧版随 detached HEAD 移动而失去恢复来源。

显式维护、独立文档任务和当前 Task 内的窄幅修正按实际范围交接，不为调度说明、文件忽略或结果整理重新建立完整业务流程。已有有效测试与审核按最终相关 Delta 判断复用或补充；仍适用的强制门禁、权限与独立性要求不省略。

## 职责命名与可读交接

以下名称各有用途，不互相代替：

| 名称 | 示例与约束 |
|---|---|
| 原生稳定角色 ID | Codex `ric_devflow_implementer`，Claude/ZCode `ric-devflow-implementer`；用于选择真实角色，不随任务标题改名 |
| 调用 `task_name` | 仅工具 Schema 支持时，首次用稳定的 `ric_<role>`，如 `ric_implementer`、`ric_reviewer`、`ric_tester`；后续用实际 ID/已确认恢复句柄继续，不以相同名字再次创建实例。已有会话保留原名字 |
| 人类可读任务标题 | 仅宿主提供对应字段时使用“实现者｜Skill布局”等中文职责与工作；没有该字段就放在交接正文，不传虚构参数 |
| 平台昵称 | 宿主展示的会话标签；是否可改名取决于真实接口，不能用角色 ID、任务名或文字自述承诺重命名 |
| Skill UI `display_name` | `agents/openai.yaml` 中的 Skill 展示名，例如“实现者｜RIC DevFlow”；不控制原生子代理昵称或既有会话 |

每次交接首行写“职责：<中文角色>｜<当前工作>”，例如“职责：测试者｜安装恢复”；接收者首条进度及返回结果同样明确自身职责和工作。当前工作在交接正文中表达，调用任务名与原生角色 ID 保持稳定；不要把临时 raw ID 或来源不明的平台昵称当作业务作者。

临时 raw ID、平台昵称与当前调用目标之间的映射保存在主会话上下文，已有 Root 的 `.local` 仅缓存相关投影；Root 关闭不删除主会话的三个槽位。正式证据继续使用原业务 ID 和真实作者，不增加状态字段、独立账本或报告矩阵。当前接口没有旧子代理重命名能力时，保留既有会话，以后续职责自述提高可读性；不为“改名”重派，不追溯修改历史。平台字段边界见[Codex 角色名称](../platforms/codex.md#角色名称与界面边界)，只在当前宿主为 Codex 且需要核对配置时读取。

## 原生平级调用

Codex、Claude Code、ZCode 的完整工作流都由主会话直接承担 Planner，三个原生子角色平级返回主会话。宿主身份来自运行声明、工具与启动上下文；仓库内配置目录或单一工具名不证明身份。身份未知/矛盾时先报告缺口，不盲目进入 Planner 或新建实例。

- **入口与独立调用**：完整开发或显式 Planner 直接加载 Planner Skill，不调用同名子代理。独立 Reviewer/Tester/Implementer 不自动创建 Root：Codex 保留显式主会话直接角色流程；Claude/ZCode 由主会话准备并调用/恢复对应原生角色，结果直接返回调用者。独立调用沿用三个槽位限制，但不让主会话因此取得 Planner 的业务写入权。
- **规则定位**：从宿主实际发现的逻辑路径确认当前角色和共享入口属于同一固定来源，按当前动作检查必要闭包；在调用参数/正文传入已确认角色入口绝对路径、共享根和适用仓库规则。独立角色不要求其他角色；不猜项目/用户优先级，不混合版本或递归搜整机。持久文件按[路径规则](../contracts/artifact-lifecycle.md#持久文件路径)记录相对位置及外部身份，不增加状态字段。
- **主会话 Planner**：唯一维护规划、状态与账本并做授权内 Git 协调。前提具备时直接执行单角色交接或已核验的不同角色并行波次，收到完整结果后按证据和门禁决定下一动作；不再依赖 Planner 子代理发回调度建议。缺少 G3 或其他必要授权时请求相应决定，不替用户批准。
- **原生调用与结果**：创建/恢复只用当前宿主真实工具 Schema、已确认原生角色和实际 ID。各平台恢复入口只在需要时查对应平台参考，不跨平台照搬参数。子角色返回完整原载荷，主会话按下节规则逐字汇入证据再更新状态，不改 Verdict/Finding、不补作者缺失 SHA。截断只向原作者请求重传，证据已落地而状态失败只补索引，不重复执行审核或测试。
- **等待与恢复**：优先宿主完成事件，状态未变不重派；同角色忙碌排队，未知生命周期先核验。用户主动取消保持停止。真实不可恢复的单实例按上节条件替换；宿主根本没有恢复能力则报告缺口，不能每次用新实例代替恢复，也不能静默改为主会话实现或审核。
- **旧 Planner 子代理迁移**：新发布源不再提供或补装 Planner 原生模板，已有安装中的旧定义保留且不调用。续接旧工作流时先确认旧 Planner 停止、写入窗口结束，取回完整规划/状态/证据与未完成交接，主会话核对后接管同一 Root。旧生命周期或证据不明时停止新增业务写入；不可同时保留两个 Planner 写入者，不改写历史作者。已误入旧 Planner 子代理只返回恢复信息，不继续调度或自行升级安装。

子角色的工具白名单不是文件路径沙箱；有 Bash 不代表只能写测试或只能读。三个子角色均不得借终端、外部客户端或 MCP 派生代理。必要环境/权限缺失时返回精确缺口，不能扩权或绕过。Reviewer 的只读性、Tester 的测试所有权和 Implementer 的单 Task 边界不因主会话接管而改变。

角色未加载、禁用、权限/来源冲突、恢复能力缺失或调用状态未知时，按[失败分类](../bootstrap.md#失败分类与重启提醒)停止受影响动作；只有符合原加载缺口条件才提示重启。指令要求主动派发不代表宿主已经调用，实机结论须有当前原生调用记录。

## 只读审核阅读缓存

仅用于 Reviewer 没有 Git/Bash 工具而需读取历史对象的情况；Codex 原只读沙箱路径不受影响。Planner 的机械提取不是审核结论，Reviewer 仍独立审核原文并返回完整载荷。

1. 用原生 Git 命令确认完整文档/代码 Commit 存在、范围及祖先关系符合意图；记录仓库身份、完整 SHA、路径/对象 ID、实际 cwd 的仓库相对值、命令、退出码和必要输出。Diff 使用禁用外部转换的 git diff --no-ext-diff --no-textconv；不能执行仓库自定义 diff 驱动来构造证据。
2. 从精确 Git 对象提取必要源码、文档和受影响邻域到 .local 的专用缓存，不复制当前工作树。可按 Git 对象 ID 复用已核验 blob 字节，但每次仍核对仓库、完整 Commit、树中路径、对象类型和模式的绑定；相同 blob 在另一 Commit/路径/模式下不是同一审核对象。Diff 缓存须同时绑定 base/head、路径范围、选项及 Git 行为条件，不能仅以内容摘要沿用另一范围的差异。
3. 保留 Diff 的删除、重命名、模式变化及完整相关原文；符号链接保留存储目标，不跟随导出仓库外内容。二进制和 gitlink/子模块变化保留类型、旧新身份及相应可审核的持久证据，不能悄悄省略。对提取字节与原对象逐项核对；在已有持久证据中保存原始身份、提取/核验命令与复现条件，交接另外给出阅读路径。只保留本轮必要缓存，不发布 Review Target 包装或整套哈希矩阵，不把 .local 路径当唯一历史来源。
4. Reviewer 对照原生命令证据、完整相关原文、差异和对象身份审核，不能只看 Planner 摘要。缺文件、缓存与身份不符、原对象不可恢复或无法执行必需检查时返回 BLOCKED，准确列出缺口；不得把“工具受限”解释成可省略适用审核维度。
5. 正式 Review 绑定原 Commit/对象而非缓存。无 Git 的正式文档继续使用已有持久快照规则，缓存不是正式快照；缺少真实代码 SHA 的门禁仍阻塞。命中前确认缓存字节完整；损坏、截断或被清理时由 Planner 从可信精确来源重建并核验，源对象缺失/不可恢复则 BLOCKED。清除整个 .local 后正式来源和复现条件仍须可恢复，不改历史结论；Reviewer 始终只读，不负责创建或修复缓存。

## 紧凑且精确的交接

每次交接只携带：Root Issue、单一角色动作或审核模式、目标产物路径/版本、适用的完整 SHA、当前 Finding/Defect、允许/受保护路径、预期输出、首个可观察检查点和停止条件。涉及 Git 写入时，另在会话/工具参数中传递实际 worktree、`base_ref/base_sha`、已有 `head_sha` 和唯一写入窗口；接收者核对 HEAD 与干净状态，detached HEAD 不视作异常。工作区绝对路径不写入持久产物，不新增 Schema 字段。完整 Spec、Task、Review、测试报告和仓库画像通过路径与身份引用，不重复粘贴；接收角色只读取当前动作必要证据与参考，链接不触发整包递归加载，同一会话已读且未变化的材料复用。

续作只补充上次交接以来的精确 Delta、身份变化、未关闭项和下一检查点，不重复未变历史。**原作者完整载荷只传一次，随后传指针**：作者首次按原模板返回全部字段，Planner 核对完整性后逐字持久化，后续交接只引用其稳定路径/记录 ID 与不可变身份。首次也可只给指针的唯一条件是宿主已提供完整、稳定、可读且可校验的原作者结果对象，接收方能取回全部原字节；摘要、临时工具输出、截断回复或未知保留期不满足该条件。Reviewer 不为传输写报告文件，仍通过宿主返回完整原文。

传输丢失/截断时请求原作者重传同一完整载荷，不重新执行工作。相同 ID/相同载荷去重，相同 ID/不同载荷停止并由原作者处理，不能取较新文本覆盖旧记录；修正以新记录声明取代。证据已完整落地但状态写入失败时只恢复索引，不重新派发审核/测试。上述传输优化不改变 v1 原路径或 v2 账本所有权；后续动作始终由同一 Planner 决定。

向审核者交接时，必须注明模式、Root Issue、目标产物/版本、适用时的 Task、代码的 `base_sha` 与 `head_sha`、发布审核的集成/tested SHA、变更预算、实现/测试证据，并明确要求只读输出。

向测试者交接时，必须注明 Root Issue、单一动作、适用的原 Task 或 Root 验证范围、当前阶段适用的 Spec/测试计划版本、基线报告及精确 SHA、预期环境和输出路径；涉及测试代码写入时还须给出允许/保护路径与预算，并确认原 Task worktree 中上一作者已停止且候选已固定。基线、计划、G5 前代码交付、修正、增量/完整/冒烟各按所需身份交接，早期基线/Root 计划不要求伪造 Task。失败先产生 Defect 证据；归因为 TEST 后可按测试代码交付修正，绝不能由测试者修改生产代码。

向实现者交接时，必须注明一个 Task 或已归因 Defect、Root Issue、Spec 版本、AC、测试计划、`base_ref` 和完整 `base_sha`、允许/受保护路径、仓库画像/参考实现、已知基线失败、预期命令，以及不得合并、不得自行创建 Task 分支和不得扩大范围的边界。普通返修同时引用已有候选 `head_sha`，接续原工作区，不从会移动的分支名猜测起点。

不得委派含糊 Prompt，再期待子角色从对话历史重建权限与身份。在平台支持上下文继承控制时，默认关闭完整历史继承，例如设置 `fork_turns: "none"`；只有当前增量无法由持久产物和 Finding/Defect 身份表达时，才附带最少的相关近期上下文。若材料过多，先按当前 ID、执行路径和受影响邻域缩小读取范围，必要时在同一 Task 内分步恢复；不得仅因上下文长度拆 Task 或改 DAG。

## 等待、恢复与中断

委派时根据风险和任务规模声明完成条件及合理执行预算。优先使用带 cursor/revision 的事件式长等待；状态未变化时不得反复读取任务、重发相同 Prompt，或仅因暂时没有 commentary 就中断正常推理。仅在明确偏离范围、持续无进展超过既定预算、等待用户输入、工具挂起或违反角色边界时中断。

等待方式服从宿主实际工具能力与时限；完成事件到达后消费完整结果，不重复催促、不为状态宣布重新取证，也不启动另一个“等待/汇总代理”。已有证据已足以决定下一步时直接推进；只有最终相关 Delta、新失败或未解决缺口才追加必要检查。

中断、超时或上下文压缩后，从 `state.yaml`、当前产物、精确 SHA 和未关闭 Finding/Defect 恢复；不得重新注入完整对话历史。用原生 worktree 清单和实际 HEAD 核对原 Task 工作区及写入者状态，路径或身份不符先停止相关写入，不创建替代分支掩盖差异。相互独立的只读调查可以并行，但共享生产路径、契约、数据、构建配置及同一 UI/模块区域始终只有一个写入所有者。

## 审核收敛

一次正式审核必须覆盖全部适用维度并返回当时可识别的所有 P0/P1/P2 Finding。规划者为每个稳定 Finding ID 记录 `resolved`、`unresolved`、`accepted` 或 `not_applicable` 处置及证据，不能只写“已按意见修改”。`accepted` 只适用于取得当前有效风险接受的 P2；P0/P1 不能接受后放行。

窄范围修正默认交回仍保持独立的同一 Reviewer 会话，提供上一 Review、待关闭 Finding、精确 Delta 和受影响邻域；新 Review 使用新 ID 并 `supersedes` 旧 Review。Reviewer 不可用/有冲突，或修订改变行为、架构边界或风险面时，执行完整复审。切换 Reviewer 时交接审核谱系，不交接完整聊天。

同一产物和审核模式连续两次 `REQUEST_CHANGES` 仍未收敛时，停止继续发布并送审新版本。先汇总重复与新增 Finding，判断根因是事实预检、Spec 结构、测试模型、架构约束还是范围失控，完成针对性修正后再送审。该规则与同一 Defect 连续三轮触发根因分析分别计数。

## 集成循环

1. 验证 Task 依赖和证据时效性。
2. 从最新已验证集成 SHA 分配就绪 Task，由 Planner 按需创建 detached worktree，记录原 `base_ref/base_sha`；功能分支即唯一集成分支，不创建 Task 分支。
3. 按[测试代码交付](test-code-delivery.md)在原 Task worktree 串行完成必要独立测试，接收各代码作者报告和完整候选的不可变 head SHA；独立 Task 是否并行仍按 Git 策略核对依赖与写入冲突。
4. 为精确 SHA 范围取得代码审核批准。
5. Planner 在授权内按仓库策略集成候选 SHA；无约定时先尝试快进，否则普通 merge 保留血缘，并记录新的集成 SHA。出现冲突则由对应作者修正并重新取得适用批准，不由 Planner 代写代码。
6. 为该 SHA 取得增量测试 `PASS`。若为最后 Task，Planner 在派发前核对[条件批量执行](../contracts/gate-policy.md#最后-task-的-g6-与-g7-条件批量执行)，符合时一次交接明确“先 G6，PASS 且输入未变才 G7”，同时给两阶段范围/输出；不符合时仍只派 G6，后续按当前证据安排 G7。
7. 先持久化有效 G6，再将 Task 标记并保持为 `VERIFIED`。批次已返回 G7 时随后核对、持久化并采纳其独立原报告，不重复派发已有效覆盖的完整验证；否则安排满足[有效依赖](../contracts/workflow-state.md#有效依赖与恢复)的新就绪 Task 或尚缺的完整验证。目标冒烟与关闭条件齐备前不置 `DONE`。

未变化的 Root Issue、仓库画像、Review、测试证据或 Decision 只通过路径和身份引用，不因局部修订复制整套产物。

## Defect 归因

测试者提供怀疑类别；最终归因归规划者所有。`SPEC` 进入变更控制；`TEST` 返回测试者按测试代码交付修正、代码复审并集成验证，只有批准计划/Oracle/环境/权限发生变化才重新测试计划审核；`IMPLEMENTATION` 在原 Task/Defect 内有界修复，随后审核新代码 SHA 并验证；`ENVIRONMENT` 记录恢复条件；`BASELINE` 评估相关性但不得扩大范围；`SCOPE_CHANGE` 进入变更控制；`UNKNOWN` 安排有针对性的只读调查。连续三轮失败触发根因分析，不自动拆分或重建 DAG。Implementer 正式交付前的正常自测修正只属于内部步骤，不为每次失败重启角色链。

## 收尾

完整验证、发布审核、目标合并和冒烟测试都必须指向当前 SHA 血缘。关闭前协调：产物存在性/取代关系、Spec/用户/测试批准、未关闭发现/Defect/阻塞项、迁移/配置/文档、基线差异、回滚和脏改动归属。记录未运行项；绝不能把它转换为 `PASS`。

报告由实际执行者在原角色会话完成，Planner 只按既有规则原样汇聚；不派生报告写作代理。收尾复用当前有效证据，只补最后相关变更所需验证；没有新变化不重复跑完整套件、重建报告矩阵或仅为宣布结束再次派发。该收敛原则不把未运行项变成成功，也不替代仍适用的独立审核。

worktree 回收按 [Git 保全规则](../contracts/git-policy.md#worktree-交接复用与保全)单独核对：全部已发布候选（含拒绝、阻塞、取代版本）可从持久历史或已验证恢复的 bundle 取回，且无活动作者、脏文件或唯一证据才可精确清理。只有最终集成树存在不代表原候选已保全；不以 Root 关闭自动授权删除既有分支或未知工作区。

## 四文件执行与预算

本节存储规则仅适用于 v2；未迁移的 v1 保持原版本路径与 transitions，通用收敛/等待规则对两者均适用。

按[Compact v2](compact-layout.md)恢复：state → 当前对象章节/独立修订 → 相关 evidence 记录。Prompt、会话 ID、cursor/revision、PID 和检查点缓存放 .local，不写进受跟踪正文；持久记录只保存业务证据与可审计角色身份。未变化且已读的共享契约不反复加载。

Planner 原样追加各角色完整载荷，先证据后状态；写入失败按 ID 核验恢复，不能为了重建状态而重新发一遍审核/测试。Reviewer 只读、Tester 拥有计划、实现者拥有代码的边界不因合并文件而改变。

调查默认一轮聚焦加一轮缺口补查；两次无新增事实停止同类搜索。当前决策已充分时进入下一门禁，继续探索必须关联具体 AC/失败/约束。下一阶段只保留能力、依赖与延期，不展开全套 Task/测试。

估算包含代码、测试、生成物和必要文档并留余量；不设置通用行数/字节硬阈值，宿主的明确硬限制和无进展熔断仍优先。事件等待的长短服从宿主工具边界；没有新状态不重发 Prompt、不重复取证，也不以暂时无 commentary 当作推理挂起。

# 后端审核

涉及服务端 Handler、Job、领域服务、Adapter 或发布边界时，加载本参考。

## 信任与所有权边界

- 追踪外部输入依次经过认证、动作授权、资源归属/租户隔离、校验、领域不变量、持久化、外部调用及响应/错误映射的完整路径。
- 协议 Handler 应足够薄，使规则可以共享和测试；但不存在真实边界时，不要凭空增加分层。
- Header、Cookie、文件名、回调、消息、存储的遗留数据和服务响应均视为不可信。
- 对外错误应稳定且安全；内部日志应保留原因和关联信息，但不得包含 secret 或个人数据。

## 正确性与可靠性

检查可重试写入、回调、Job 和消费者的幂等/去重；短事务边界；尽可能把外部调用放在事务之外；超时/取消；仅针对瞬时故障、有上限且带退避/抖动的重试；有界分页和稳定排序；资源清理；优雅关闭；以及可见的后台任务失败/死信行为。

并发规则必须在权威层通过数据库或适当原子原语执行，不能只依赖“先检查后写入”的顺序。

## 兼容性与运维

除非已批准变更，否则保持 API、事件、配置、数据和错误契约。审核旧调用方、滚动部署、默认值、未知枚举处理及迁移顺序。确认 liveness/readiness 语义；为高成本或易滥用端点配置限流；提供结构化、低基数遥测，以及可操作的运维关联信息。

优先使用已有库和本地模式。新依赖必须对应具体能力缺口，许可证和维护状态兼容，供应链影响有界，并且纳入已批准变更预算。

# 前端体验与审核

所有用户可见的界面变更都采用本参考，包括文案、局部组件、内部工具与公开页面。按当前阶段和实际影响选择检查深度。轻量维护在原完成清单与交付记录中执行相称的对标、自查和取证。

## 成品品质对标

- 用适合目标用户的数字体验作为质量参照。检查用户能否迅速理解页面和完成任务、内容与导航是否清楚、视觉层级和细节是否一致、交互反馈与恢复是否及时，以及可访问性、性能和整体体验。创意应服务于用户任务和项目表达。相关公开参考包括 [Awwwards 移动体验指南](https://www.awwwards.com/mobile-excellence-guidelines.pdf)、[The FWA 入选作品](https://thefwa.com/)及 [Webby Awards 评审标准](https://www.webbyawards.com/judging-criteria/)。
- 为每次界面改动记录至少一个相关参考及可借鉴的具体做法。已有产品优先引用批准的设计稿、既有设计系统或成熟相邻页面，按需要补充适合的获奖案例。用路径、组件或可读取的链接定位来源，说明采用的做法如何服务当前用户任务。已有可信参考可以直接复用。
- 在现有 UI 规格中记录目标用户、主要任务、参考、视觉或交互取舍与可观察的验收条件，绑定现有 AC。局部改动核对受影响组件及必要上下文。新页面或流程改版核对关键页面、真实长度的内容、目标断点、主路径及适用的失败恢复。依据项目获批条件和实际证据判断达成度。

## 面向用户的界面文案

- 用目标用户熟悉的词描述动作、对象与结果。按钮直接说能做什么，提示提供当前需要的信息。专业用户完成任务所需的领域术语沿用项目用词，首次出现时按需要简短解释。
- 错误与恢复提示说清发生了什么，以及用户可以做什么。加载超时时可提示「暂时无法加载清单，请稍后重试」。协议状态、内部字段和实现细节留在适用的诊断位置。提示与当前结果一致，提交结果未知时如实说明。

## 产品与状态行为

- 从真实路由/动作追踪主要流程和恢复流程，并保持 Spec 范围外的 URL、导航、历史记录和既有交互契约。
- 覆盖加载、空数据、错误、成功、禁用、无权限、离线、部分成功、重复提交、过期响应及卸载/取消行为。
- 状态放在最小合理作用域：可分享状态放 URL，远端数据放仓库既有 server-state 层，表单状态留在表单，局部 UI 状态保持局部。不得引入平行状态系统。
- 乐观更新必须有明确回滚和服务端对账路径。

## 优先使用现有设计系统

识别并复用组件、Token、图标、布局原语、反馈模式和相邻页面。拒绝引入第二套组件库、隔离的 Token 集合或无关视觉重设计。使用真实内容长度和目标断点验证；项目支持时覆盖移动端、平板和桌面端。

## 可访问性与国际化

检查语义元素、可访问名称、键盘顺序/操作、可见焦点、对话框/错误/导航后的焦点移动、实时播报、对比度、减少动态效果、触控目标、缩放/重排和屏幕阅读器状态。消息、复数、日期、数字、货币和 RTL 使用既有 i18n 系统；不得拼接自然语言片段。

## 安全与性能

把所有渲染数据视为不可信。检查 XSS、不安全 HTML/URL、开放重定向、进入查询参数/本地存储/日志的敏感数据、CSRF 假设和服务端授权。根据真实风险或测量结果检查请求瀑布、代码/图片体积、Hydration/运行时边界、列表上限/虚拟化和缓存行为。不得一概 memoize。

## 实机自查与取证

- 用仓库已有方式在浏览器、对应客户端或可操作的组件预览中检查实际界面。检查布局、排版、间距、层级、文案、操作和状态反馈，并按影响复查键盘、目标视口和恢复路径。用用户可观察的结果做断言。截图或录屏描述视觉状态，实际操作记录证明交互结果。
- 按「检查 → 记录问题 → 修正 → 复验」推进。每轮在本次范围内记录问题、具体修正与复验结果，继续处理仍影响获批验收的缺口。局部改动保留相称的预览或前后对照与操作结果。新页面或流程改版保留关键状态截图或录屏及实际操作结果。通过现有报告或交付记录引用证据，并绑定当前验收项、环境和候选身份。
- 获批条件有证据支持时完成。达到既有[收尾与有效进展规则](orchestration.md#收尾与有效进展)的暂停条件时，报告剩余缺口及下一项有效动作。环境或工具缺失时完成可用检查，记录缺失能力、受影响验收项、未运行原因和解除条件。必需证据缺失时按现有门禁处理受影响部分。

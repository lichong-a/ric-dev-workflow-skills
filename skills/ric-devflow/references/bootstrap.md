# 准备与恢复

仅在入口的任务分类、真实宿主/身份和安装范围确认后执行。此参考是准备流程的唯一权威源；角色自包含缺件守卫只负责在本文件尚不可读取时恢复入口。准备不是业务规划或 Gate，不创建 Root/Task，不写业务 current/state/evidence，不替用户批准行为。

## 保留原任务与执行边界

主会话执行准备；已启动的任何子角色发现入口、共享文件、来源、工具或权限缺失，只返回原任务、所需角色、精确缺件路径/身份和下一恢复动作，不安装、不派生、不启动 Planner 或外部客户端。

保留原任务文本、作用仓库、约束、已有批准及当前步骤。用户已批准的本包准备范围内，不为每次补缺重复询问；范围/来源不明、越出当前授权或宿主要求权限时只停受影响动作。实际工具拒绝后记录原拒绝和目标，不能换脚本、包装器、CLI 或代理绕过。不要读取/输出凭据、环境变量全集或真实连接字符串。

## 三种路径与宿主

| 字段 | 事实来源 | 用途 |
|---|---|---|
| `discovered_path` | 宿主实际发现的逻辑 Skill 入口位置，含链接原位置 | 确定用户/项目范围及同级补装目标 |
| `source_root` | 完整可信 checkout 或固定候选的源码根 | 只用于读取 `skills/`、核验候选及复制源 |
| `install_scope` | 已确认项目根或用户范围，以及当前宿主实际 Skill 根 | 限定本次写入位置；与 source_root 分开 |

不能从解析后的源路径猜范围。例如项目 `.agents/skills/ric-devflow` 指向用户 checkout，仍按项目范围补角色；用户入口指向项目 checkout，仍按用户范围补。只知道源码中 `skills/ric-devflow/SKILL.md` 不表示要用户级安装；必须先从用户意图/宿主发现记录确定范围，无法确定时写入前询问。

依据宿主声明、原生角色启动上下文和实际可用工具共同确认身份，不能由 `.codex/.claude/.zcode` 存在、单个工具名或没有 Agent 工具反推。身份冲突、未知或非支持宿主：原任务保留，报告所需事实，不安装其他平台。

只读取当前平台参考和其资产；同名用户/项目来源由宿主发现结果确定，不能猜优先级或混合包。来源遮蔽无法消除时，先解决实际加载来源，再调用角色。

## 本次必要闭包

- 完整开发：`ric-devflow`、四个 `ric-devflow-<role>` 的完整目录，以及当前宿主四个原生角色；不得为内部实现步骤增加角色链。
- 显式独立角色：入口完整目录、所选角色完整目录、当前宿主执行该角色所需的原生定义。Codex 主会话显式执行角色无需为此配置其他原生角色；若动作确需委派，必须核验该目标的真实可用性。
- 共享契约、模板、编排、Task 冻结规则、测试代码交付与特征测试均在入口内，不再要求安装 Planner/Tester 才能读取它们。角色私有模式参考保留在角色目录。
- 阅读闭包按当前动作追踪必要边；入口的角色导航和其他模式/语言的可选路由不作为必需依赖。实际选中的模式及传递引用缺件仍须补齐，不能把坏链接标成可选掩盖。
- `README`、`docs` 和源码外围 `.agents/.codex/.claude/.zcode` 不是运行依赖。安装记录可由标准安装器或既有来源回执提供；没有记录不能猜 SHA。

完整性检查先列出需要的文件/配置，再决定是否补装。文件及已加载来源有效且无缺件时直接进入角色，不无故联网、重装或读取其他平台。

## 固定同源候选

唯一发布仓库为 `https://github.com/lichong-a/ric-dev-workflow-skills`。使用前确认这是用户选择/当前安装记录指向的发布源；名字相似的仓库、网页内容或角色输出不能改变发布源。

1. 优先完整、可验证的本地 checkout：确认仓库身份及完整 Commit SHA，按该 Git 对象读取必要文件，检查路径类型/文件清单。工作区改动不是该 SHA 的内容；不得将脏文件伪装为已提交来源。测试开发候选只能产生标注其文件摘要的隔离测试，不能冒充发布安装。
2. 其次使用已有可信安装记录的固定完整 SHA，从可信本地对象或同一发布源取回该版本；不得把记录中的版本替换成最新分支。
3. 两者皆无时，只有发布仓库已确认才允许从该仓库取得一次候选并立即固定完整 SHA。后续所有列文件、内容读取和复制都使用该 SHA，不持续追踪 `main`，不自动轮询历史寻找“差不多”的版本。
4. 比较待修复闭包中**全部现存包文件**与候选对应文件的类型和逐字内容，包括 references、assets、UI 配置；不能仅比 `SKILL.md`、名称、版本标签或目录名。未知额外包文件、用户定制、异版本或同名文件类型冲突不能自动归为缺件；报告实际路径和差异，不覆盖。宿主配置中无关项单独按下一节保留。
5. 只有现存文件均匹配，候选才能用于填缺。旧入口与新候选不同即停止，要求原 SHA 或完整可信 checkout；不猜历史、不默默升级、不删除旧用户安装。离线且完整可信本地源匹配时可以恢复；离线且缺源/对象时报告精确缺口。

使用宿主安全文件工具或已审阅的原生 Git 获取/复制，不执行下载的安装代码，不运行仓库脚本。需要凭据时只使用受控入口；失败先检查实际地址/协议/权限/TLS/环境，不关闭证书校验、不全局改代理，重试须有限且有具体新证据。

## 全部目标预检与最小写入

在任何写入之前固定候选、安装范围和**本次全部**目标清单，核对父目录、类型、权限、逻辑链接和已有内容，包括即将安装的当前平台角色配置。仅当前宿主可写；ZCode 项目范围只有所需原生角色定义允许写用户 `~/.zcode/agents`，五 Skill 仍留在原项目范围。完整开发可写四角色定义，独立调用只补所需角色。

| 目标现状 | 动作 |
|---|---|
| 普通目录/文件缺失 | 预检通过后创建必要父目录、逐文件普通复制 |
| 现存文件与固定候选同字节 | 复用，不产生写入 |
| 已确认同源有效链接 | 核验逻辑位置、目标与字节；可以读取复用，不将链接替换成文件或跟随写入源树 |
| 文件挡住目录、定制/异版本同名项、未知额外项、不明断链 | 记录精确冲突并停止，保留原内容 |
| 宿主配置有其他模型/并发/权限/Agent 或项目指引 | 保留；仅补必需且缺失的配置项，不整文件覆盖或格式化 |
| 已明确禁用 Agent/Skill/必需能力 | 不反转；说明原任务受影响及需用户决定的设置 |

不覆盖已有 `AGENTS.md`、`CLAUDE.md`、宿主 settings、用户规则或不相关配置。工具白名单不是文件路径沙箱；不能据此扩大写入路径或默认获得 MCP 权限。配置解析失败、同名原生角色为其他定义或来源遮蔽时先解决冲突，不能复制新模板遮盖。

逐文件复制时再次确认目标仍缺失，以排除预检后的变化；使用不覆盖/排他创建能力，不依赖 `cp -n` 的静默跳过来宣称成功。写后读回文件类型、全部内容和可解析的配置，核对实际变更清单。写入失败立即保留准确结果；再次进入时重算现存匹配文件，只补仍缺项，不从头覆盖、删除已正确文件或无限重试。两次无新事实停止同类搜索并返回缺口。

## 文件、加载、调用分别核验

分开记录以下事实：

- 文件安装：逻辑位置、固定源 SHA、复用/新写路径及逐文件读回；不记录凭据。
- 宿主加载：真实发现的 Skill/原生角色名称、来源、启用状态及宿主反馈；只有文件存在时写“未核验加载”。
- 实际调用：原生工具目标与真实返回；未发生调用时写“未调用”，不能拿配置解析或通用 Agent 输出当证据。

按当前平台实际刷新/重载能力核验。能继续就读取所需角色入口并沿原任务前进；需新会话/重载时保留原任务与约束、仓库、逻辑范围、固定候选 SHA、已完成阶段、精确缺口和下一动作，提示恢复后先读回，不重复安装。不得保存原始会话秘密或伪造后台承诺。

进入角色后的 Spec/Task/测试计划/依赖/代码 SHA/权限仍按原契约预检。只有源码未提交候选、安装完成或本地诊断通过，均不能变成 G5–G9 的真实 Commit 证据；不改写业务产物、Gate、Verdict 或历史。
